# 炼药锅与滴水集液验证（0.68）

## 实施前的设计判断

1. 结构：让真实液体源、滴水石、炼药锅和桶形成可持续取水 / 燃料流程，并接入既有合成、信号和保存入口。
2. 负担：玩家只选择放置位置和使用的物品，液体来源、遮挡、容量和比较器输出由世界推导。
3. 可推导：使用方块类型表达空锅、三档水量和满锅岩浆，不另存一份可漂移的容量或液体记录。
4. 复杂度：复用七格合成、物品交换、形状渲染 / 碰撞、天气列、体素光和 v16 方块保存，不添加设置、依赖或专用 UI 面板。
5. 泛化：手动装取、降雨、不同长度钟乳石和不同维度共用同一组合法锅状态；随机集液只处理已加载的当前世界。

最小完整变化包含可合成 / 放置的真实空腔锅、桶与水瓶交换、雨水及滴水集液、接触水灭火 / 岩浆伤害和 0–3 比较器读数。完整方块外观加一个取水按钮无法提供实际容量、身体接触与源头遮挡玩法。沿用现有随机更新，不增加离线补算或进度字段。

依据 [Minecraft Java 1.17 官方说明](https://www.minecraft.net/en-us/article/caves---cliffs--part-i-out-today-java)中的水源 / 岩浆源经钟乳石集液机制。六棱配方与几何为本项目版本，不声称逐刻复刻 Java 版。

## 实施前列出的失败类别

- 合成不扣七铁、不能通过生存放置和回收；盛液状态错误出现在创造物品栏，拆锅掉出额外液体或错误变体。
- 桶不能装满 / 收取、未满锅也能取整桶、非水 / 岩浆物品误改变内容、不同液体混合或满锅继续消耗水瓶。整桶倒入会替换原内容并返还空桶。
- 三次水瓶取放不能守恒；堆叠玻璃瓶、副手和满背包交换导致容器丢失、复制或错误饮用水瓶。
- 空腔、边壁、锅底、液面和手持 / 图标几何不一致，玩家站在液面上，或站在锅沿也被当作浸入。
- 水锅不灭火、未燃烧也扣水、每帧重复扣水；岩浆不伤害 / 点燃或消耗内容，抗火和创造模式失效；锅内误进入游泳或窒息状态。
- 滴水石源必须是真实水 / 岩浆源，流水、无支撑、朝上、相接尖端、淹没尖端、断链、液体间隙及实物遮挡不能集液。
- 只处理最近的可接液锅，限制竖向距离；已满或装有另一种液体不覆盖；不同长度链和负坐标不能误用固定位置。
- 晴天、沙漠、雪原、遮挡、上方液体和其他维度误收雨水；空锅与部分水锅收集正常，岩浆不被雨替换。
- 随机事件无视 dt / 暂停，卸载区块或非当前维度继续更新，保存后补算离线收益，或每帧重新生成随机定时器。
- 比较器未读 0 / 1 / 2 / 3、水量变动后信号不更新，岩浆错误输出 15，隔实心方块读取失效。
- 岩浆锅未加入实际彩色光，取出后残留发光；锅内液体错误产生世界流动、焦散或整个锅体透明。
- 保存 / Continue / 维度往返后内容丢失，无法拒绝不存在的盛液变体；既有桶、瓶、滴水石、红石和库存行为退化。

## 范围与实现限制

- 水、岩浆和三档水量为五种合法方块类型，仍使用现有 v16 方块编辑记录；没有新增液体进度或离线计时。手动整桶会替换原内容，自动收集不覆盖另一种液体。
- 集液目前要求尖端下方同列空气通路，最大向上搜索 11 格；阻挡物与液体中断通路。尚未细分允许滴液穿过的非完整碰撞形状，也未实现含水尖锥。
- 使用随 dt 变化的泊松近似，水滴每档平均约 400 秒，岩浆满锅平均约 1200 秒，满强度雨水每档平均约 1200 秒。随机时长无固定保证，不复刻 Java 随机刻调度或离线收益；浏览器验证控制随机边界，没有等待完整统计周期。
- 水锅灭火与岩浆接触伤害本轮接入玩家；锅内生物、掉落物销毁、细雪、染色 / 清洗、村民职业和自然生成锅尚未扩展。现有水瓶可用于已有酿造台，不提供基岩版药水锅。
- 取桶仍由玩家操作，未实现发射器装桶；漏斗不会抽取锅中液体。源头取液后的燃料用途通过实际熔炉流程验证，未单独跑全部炉具或炼药锅跨维度 UI 往返。
- 锅体使用现有铁质像素面板，液面为不支撑身体的静态几何，可被瞄准；锅内水不会进入世界流体、游泳或窒息计算。尚未接入完整水面折射 / 全反射和液面动画；本轮没有改动 Photon 光学算法。
- 截图来自无头 Chrome 软件渲染；PNG 颜色差是显示采样，未作物理照度或用户显卡帧率验收。

## 交付后的设计检查

容量和液体种类是固定方块定义的元数据，世界只保存当前方块类型。手动装取及可用手选择共用 `cauldronAction`，自动收集和灭火共用水量状态，渲染、身体接触与滴落终点共用液位高度。没有第二份液体库存、独立保存表或无人读取的配置。

几何通过已有 `buildingParts` 同时服务世界、碰撞、手持、掉落物及图标，碰撞查询只排除液面。`dripAbove` 是集液模块内部的有界扫描，单独保留以便逐层提前退出，不引入搜索状态、可插拔策略或缓存。实体发光复用原有体素光，桶和瓶的余物继续使用原有物品交换和满包散落逻辑。

盛液变体的 `drop` 通过已有形状拆除入口读取；其他受影响定义只有原本即返回相同物品的红石线和门上半部。中键把盛液变体归为空锅，避免把内部方块变成可携带盛液容器。没有新的玩家设置、依赖、图片资产、渲染目标或测试专用产品分支。

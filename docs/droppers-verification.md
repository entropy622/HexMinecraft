# 投掷器验证（0.75）

## 实施前判断

1. 结构：复用红石延时和真实容器端点，实现定向单件运输与物品喷出，补上漏斗不能向上运输的玩法。
2. 负担：玩家沿用放置、右键容器、拉杆 / 按钮和现有合成，不增加配置、测试开关或第二套容器。
3. 可推导：放置朝向取自玩家视线，触发取自红石上升沿，输出位置和插入面由方向推导。
4. 复杂度：沿用红石计时、库存、散落物和比较器；增加投掷动作与出口外观，不建立额外调度器或物品复制路径。
5. 泛化：六个水平和上下出口、任意合法物品、空箱 / 满箱、跨区块、卸载 / 保存继续、破坏与重新上电均走相同链路。

最小完整方案是九槽容器、上升沿后的 0.2 秒延时、随机非空槽的一件物品，以及前方容器插入 / 实体掉落。仅做 UI 或按钮回调不能工作于真实红石。投掷器先形成定向容器与脉冲基础，发射器专用射击 / 放置 / 使用行为继续推进，不能用一个同名只会掉落物品的方块替代。

参考 [官方投掷器介绍](https://www.minecraft.net/nl-nl/article/block-week--dropper)的九格、单件和向上容器运输；发射器的物品行为与投掷器不同。

## 实施前失败类别

- 无法合成、真实放置、辨认朝向、打开九槽或移动物品；配方未保留七圆石加一红石的材料量。
- 持续高电平重复输出；短脉冲被取消；延时内重复信号多发；物品穿越尚未收到脉冲或尚未到期的节点。
- 按物品数量而非非空槽随机；一次多件；满容器仍消耗 / 掉在地上；空箱抛错。
- 向上下或负坐标跨块错误；目标未加载时丢失物品；源卸载时计时继续；保存继续重复触发。
- 自动插入忽略炉具 / 酿造台的入口面或只读输出；便携容器嵌套规则被绕过。
- 药箭变成发射物、桶被使用、耐久 / 附魔 / 名字 / 盒内物品丢失；破坏时库存消失或双倍掉落。
- 比较器读错九格容量；漏斗补给与提取读到另一份库存；实体碰撞和顶面支撑不匹配。
- 新朝向放宽了其他方块存档；非法计时、重复和孤立记录进入保存。
- 操作、红石、比较器与漏斗回归；验证抢占前台鼠标。

## 结果

- 实现前浏览器基线在真实工作台找不到投掷器配方，按预期失败；保留在证据目录的 `baseline/` 与 `browser-baseline.log`。
- `npm test`：**90 / 90** 通过，包含七组投掷器失败类别。使用真实 World、Redstone、槽位、ItemDrops、合成和原生存档；只在随机槽选择检查中控制外部 `Math.random`。覆盖八向 / 负坐标、随机非空格、满箱、三类物品元数据、加工端口、比较器、短脉冲、剩余延时恢复与损坏存档。
- `npm run build`：**0.75.0 生产构建通过**。最后一次图标修改后重新构建成功；仍有既有的大 bundle 提示。
- 浏览器回归批次 **19 / 20** 通过，唯一失败是水平场景再次点击时，拉杆柄部转动后离开固定射线。修正测试为瞄准底座并断言每次通断，另补手机布局、图标细节和精简的输出清单后，本轮三个场景 **3 / 3** 通过。合计覆盖 **20 个不同场景**，并非声称最初批次全绿。
- 其余十七个场景包括五个比较器、四个漏斗、四个红石、三个操作和一个跨维度 / 各画质档渲染。共享槽入口没有破坏自动炉具加工、经验留存、工具及潜影盒回收和触屏漏斗操作；图形回归无着色器错误。

## 范围与限制

- 六个水平与上下方向属于六棱世界实现；浏览器实际放置覆盖水平和向上，其余方向及负坐标由真实世界组合检查覆盖。没有声称复刻 Java 版准连接、所有邻居更新优先级或大规模机器性能。
- 投掷器输出物品；发射器专用的射箭、装倒桶、点火和其他物品使用尚未实现。本轮不注册一个只会掉落物品的“发射器”。
- 源未加载时冻结剩余延时，目标未加载或自然宝箱尚未发现时保留库存，已到期动作不会在目标恢复后自动补发。暂停和其他维度沿用现有模拟规则，不计算离线运输。
- 炉具和酿造台接收面复用现有端点规则，向上插入炉底仅接受空桶；没有新增药水类型或过滤器配置。设备空转 / 拒收和成功输出使用不同音高，本轮未做人工听感验收。
- 本轮手机检查验证布局，完整触屏取放由现有漏斗回归覆盖；没有另跑投掷器的全部触屏手势。向上口部可被箱子实际遮住；模型不穿透显示出口。
- 本轮继续扩展生产玩法，Photon 风格算法沿用 0.74；新增实心投掷器按完整方块阻光。软件渲染截图与构建通过不等于用户显卡性能验收。

## 交付后的设计检查

逐项复核本轮所有产品差异、投掷模块、两份新测试、README / 开发状态 / 本记录和两份包元数据。手动 UI、漏斗、投掷器和比较器仍访问一份 `World.chests` 库存；共享的 `insertionSlots` 有漏斗和投掷器两个生产调用方，没有增加库存副本或测试专用产品入口。

出口复用 `facing` 的 0–7，`powered` 仍是方块实际通电状态；仅投掷器允许垂直朝向，其他方块的保存范围保持 0–5。等待动作复用 Redstone 的现有计时表及 v16，最大值为 0.2，没有额外调度器、持久化队列、迁移或兼容读取分支。Redstone 通过生产回调调用持有场景的 ItemDrops，沿用现有门动作的边界；只在上升沿排定动作，不把库存变化误作新触发。

同一 `buildingParts` 几何供世界、实体碰撞、手持、散落物和 SVG 图标使用；完整实形在导电、支撑与体素阻光中明确处理。素材为现有程序绘制和 SVG，无新图片、依赖、玩家配置或渲染目标。修改文件通过 Prettier，`git diff --check` 通过。

净变化：产品 +209 行，测试 +711 行，文档 +71 行，配置 +0 行。产品增长用于真实动作、共享端点、完整实形、口部与 UI；测试覆盖生产入口和边界，没有源码文本断言或内部模块替身。

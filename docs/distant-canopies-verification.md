# 自然远树的三维冠层与紧凑几何（0.128）

本批继续改善 Photon 森林参考图中的冠层形态与近远关系。完整 MC/Photon 目标仍未完成。

## 行为

0.127 只保存每个 4×4 柱组的最高树叶，再补出统一的小冠层与细树干。0.128 保留实际世界生成的自然树叶和原木在水平 2×2、垂直一格的三维占据，按暴露表面绘制。巨树枝冠、较低叶层、树干和倒木由真实方块分布决定，不再从最高点猜一个树形；相邻实体表面不画内部面。

地面继续使用 4×4 最高柱。生成片仍覆盖 40×40 轴坐标与 25 个临时区块，但把显示核心内移四格，给两侧都保留邻居数据。移动窗口使用相同偏移；源编辑的失效仍按实际数据片范围处理。未扩大玩法区块、碰撞、瞄准或远处模拟。

六棱体使用索引面，合并面内重复顶点。位置保留 Float32，法线使用归一化 Int8，颜色/可见性使用归一化 Uint8，UV 使用归一化 Uint16；材质分类字节继续不归一化，群系颜色继续归一化。所有属性仍显式绑定，避免不同场景的通用顶点常量互相继承。资源包切换按新图集重新建立远景几何。

远处叶片使用既有 Photon 参考叶片函数，接入向上天空漫反射、主透光、sheen 和远影零厚度响应，并保留共享日月光与云影。没有把近处光学体积之外的未知空间当作完整可追踪的森林。它仍是粗略远景响应，不能替代真实的逐光线树叶厚度与遮挡。

## 证据

4 项相关 Node 检查通过，覆盖真实自然树数据在负坐标相邻片的相同重叠区域、索引/归一化属性与新增下表面、细柱建筑的替换/挖除/水源、连续树冠跨片剔面，以及编辑版本。生产构建和变更文件格式检查通过。本批没有重复执行未修改的高光公式输入矩阵，也没有把几何采样或渲染帧数计为功能场景。

最终开发版为 **1 项实际场景流程**：同一自然丛林镜头、32× 叶片资源包导入/恢复、两个区域边界位置、远处同坐标木柱替换为石柱、长距离传送、三个画质档和一次真实显卡上下文恢复。跨边界的第一帧分别记录 `center=-6,1` / `-5,1`，两帧的 `ready` 都为 true；没有等新窗口完全补齐才判定连续。生成任务仍最多 25 区块，完整玩法区块仍为 529。

已查看原生丛林、资源包、恢复默认材质和画质截图。巨树有宽窄不同的实际枝冠和较低叶层，较 0.127 的统一小冠层更接近自然生成。恢复前后时间、相机、编辑记录与 169 片数据保持一致，页面和 GL 诊断无异常。恢复截图带正常暂停面板，画面判断使用此前无面板的实景截图。

发布版另有 **1 项真实控件流程**，导入/导出带远处建筑的 v16 存档。观察实际 WebGL 的远景混合参数到达 1 后，才记录帧耗时并导出；生产开发 API 不存在，时间、位置、天气、库存和编辑记录保持一致，没有锁定鼠标。

同镜头的 169 片窗口有 1,632,062 个顶点、886,438 个三角形，属性加索引 **60,808,736 B，约 58.0 MiB**，低于 0.127 的约 115.0 MiB。CPU 树冠占据数组另有 **8,652,800 B，约 8.25 MiB**；现有 HDR 颜色/深度目标保持约 6.70 MiB。几何类型数组在 CPU 保留并上传 GPU，树冠数组保留在 CPU；这些不是进程峰值内存或显存。形状和存储格式同时变化，差值不能全部归因于单项压缩。

本次三角形从 0.127 的约 52.2 万增加到约 88.6 万。固定 900×650、光影档、同一丛林存档记录 80 个正常渲染帧，GPU 中位 **27.921 ms**、p95 **36.275 ms**，CPU 提交中位 **34.2 ms**，RAF 间隔中位 **33.4 ms**，查询 busy/disjoint 均为零。上批独立记录 GPU 中位约 25.5 ms；两次不是同进程配对计时，不能据此断言稳定的增量成本，也不能将减少几何内存说成帧率提升。计时窗口无截图和像素读回。

最初三维树冠实现仍把负方向边界当作空邻居。连续树冠的独立几何复现出现 768 个内部侧面顶点；显示核心内移后，此复现不再产生任何内部竖面，且保持每个生成任务 25 区块。此前的截图和批次留存，未改动运行中的源码。

## 限制

自然树仍为水平二格的粗化形状，近远材质与轮廓交接仍可见，远叶尚无完整环境透光缓存、精确厚度或风动画。玩家建筑与编辑/种植树木仍沿用柱组近似。本批没有改变晴天的近景交接 87.32～118、远景封边 176.12～238、完整玩法视距 10 或 v16 存档。

首次生成仍需数十秒，三维占据数据增加了 CPU 存储；压缩几何的收益须与这部分一起评估。单场景性能不能外推到全部群系和建筑。更多复杂建筑、水面镜头与快速长距离移动仍需继续验收。

# 角色开销与整世界帧时

**单角色渲染**：RTX 4060、后台 Edge / D3D11，1366 × 768。六野角色室用同一模型、动作与相机交替显示和隐藏模型；每组提交 6 帧后读回一个像素，等待 GPU 完成。24 组取中位数，含地板和动画更新。显示角色为 **0.30 ms/帧**，隐藏为 **0.17 ms/帧**；两组 P90 分别为 0.35、0.20 ms。模型本身每遍 30 次绘制、2,594 个三角面。

**生存世界第三人称**：相同显卡、后台 Edge / D3D11、1366 × 768、画质 0.65。进入新世界，切换 F5，固定相机，等近景区块网格队列清空。保留同一套动画更新，仅切换角色网格的渲染层。交错采样 16 段，各状态各 64 个显示帧间隔：

| 实景 | 中位帧间隔 | P90 帧间隔 |
| --- | ---: | ---: |
| 显示角色 | 100.0 ms | 866.7 ms |
| 隐藏角色 | 99.9 ms | 166.7 ms |

第二次新世界采样同时启用了浏览器 CPU 采样器：显示角色时中位数 / P90 为 83.4 / 166.6 ms，隐藏角色时为 99.9 / 866.7 ms。这次长帧集中在隐藏组。CPU 自身耗时最高的两项是藤蔓更新和支撑面检查（18.0% 和 9.8%）；另有叶片环境光更新、区块重建及体素光照开销。

**结论：**角色几何本身的绘制开销较小。六野整世界约 10–12 FPS，两次测试都遇到了长帧，整场景尚未达到流畅目标。优先排查世界模拟对藤蔓和区块的重复更新。这里测的是六野，Minecraft Java 的帧率需用目标游戏实例测量。

`node tools/pearl_hy/profile.mjs` 可复现角色室采样；设置环境变量 `PEARL_PROFILE=1` 后运行 `npx playwright test -c tests/field-models.config.js -g "back, front"` 可复现实景采样。录制转台时按固定时间步推进，录像帧率与性能采样分开。

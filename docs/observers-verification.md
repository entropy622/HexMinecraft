# 侦测器设计与验收

## 实现前的五个判断

1. 结构性：在真实 World、液体与红石变更入口通知相邻的已加载 `circuitCells` 侦测器，任何正常玩家和机关路径都能被观察。
2. 调用负担：玩家只选放置位置和视线方向，内部复用 `facing`、`powered` 与现有红石计时；`setState` 的 `record=false` 与已有 `set` 一致，用于玩家放置、补全半砖和门开合的实际碰撞试探。
3. 可推导信息：检测面由视线确定，输出在相反面；目标和信号均从真实世界推导。
4. 最小复杂度：每次提交只检查八个相邻格，并使用既有计时器，不增加事件总线、全世界扫描、队列存档格式或资源依赖。
5. 泛化：覆盖方块放置/移除、朝向/开关等持久状态、液体实际状态与红石线强度，且可观察另一台侦测器；不绑定演示按钮。

最小方案是在真实提交方块/标量状态、液体或线信号时通知检测面正对该格的侦测器，有变化后等待 0.1 秒输出 15，再于 0.1 秒后关闭。逐物理步比较快照虽然更少代码，但会漏掉有效的 A→B→A。玩家试放使用 `record=false` 并先撤回临时表示，再真实提交；失败回滚不通知，不引入通用事务框架。

## 官方依据与范围

- [Minecraft 的 Observer 介绍](https://www.minecraft.net/en-us/article/block-week-observer)确认定向检测、观察其他侦测器、强信号短脉冲，并明确 Java 与 Bedrock 的检测差异。
- [Microsoft 红石指南](https://learn.microsoft.com/en-us/minecraft/creator/documents/redstoneguide?view=minecraft-bedrock-stable)说明观察面检测更新、相反红点输出一红石刻。
- [Mojang 原始配方](https://github.com/Mojang/bedrock-samples/blob/main/behavior_pack/recipes/observer.json)为六圆石、二红石、一石英；本项目七格合成界面用已有每格数量机制表达完整九件成本。

六棱世界有六个水平朝向及上下，共八方向；`facing` 表示检测面，输出为相反方向。检测面双眼，输出面红点会随脉冲亮起，目标提示显示两面方向和 0/15 输出。

检测正面一格已提交的方块种类、`World.state` 的持久标量状态、液体种类/源/流级/下落状态、红石线强度。库存内容、熔炉进度、作物实体数据和临时碰撞放置不属于本次范围；容器可通过已有比较器把内容变化转为可检测的方块输出状态。相同值不触发；等待及脉冲期间变化合并，不延长脉冲；同一步内有效的 A→B→A 仍保留一次脉冲。不承诺 Java BUD、完整更新顺序或跨卸载追赶。

目标或侦测器未加载时不通知，生成/加载区块不视为变化。既有红石计时器冻结侦测器所在未加载区块的剩余时间；等待和亮起阶段均随存档恢复。拆除删除计时器。被活塞移动的侦测器关闭旧输出并在目的地重新延时发出一个短脉冲。

## 实现前列出的失败类别

- 配方少收费、无工作台也合成、缺任一材料仍出货、失败时库存/合成格丢物或复制。
- 任一水平或垂直方向观察错面、侧面漏电、不能强充输出方块、模型/图标/手持不一致。
- 放置/加载误触发、稳定状态重复触发、同值重写（含空格重复清空）触发、状态变化遗漏、液体或线信号变化遗漏。
- 同一物理步有效 A→B→A 被漏掉，或试放/状态试探后回滚误触发、遗留持久状态。
- 0.1 秒前输出、边界迟到、重复延长、快速变化取消应有脉冲、大步长吃掉下一阶段、链路在一个步内穿透多级。
- 灯持续亮、活塞不动作、投掷器/漏斗无法使用脉冲、容器传输不守恒、侦测器本身错误导电。
- 拆除后幽灵脉冲、移动后永久亮起、卸载时消耗计时、加载时假脉冲、等待/亮起存档丢失、非法计时或方向被存档接受。

## 先行玩家 E2E

`tests/observers.spec.js` 从生存开始，经工作台配方 UI 消耗六圆石、二红石、一石英合成一台侦测器，经右键放置令双眼朝向目标拉杆，输出连接真实投掷器与箱子。玩家右键切换拉杆后只转移一件；保持拉杆不动不会持续出货；再切换才再出一件。保存并继续后复用机关，留截图与规范化 JSON 清单。只替代 `tests/browser-fixture.js` 已注册的原生 Pointer Lock 设备边界。

第二条玩家流程直接尝试在自身碰撞体内放置普通方块和带状态的侦测器，确认两次均被实际放置路径拒绝，库存不变、无残留持久状态且连接的投掷器没有假出货。

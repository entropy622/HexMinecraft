# 0.84 草地、地毯与侦测器组合验收

三个独立 feature 在 0.83 上开发，经逐行复查后整合。没有新增依赖或存档格式，继续使用 v16。

## 组合前的设计判断

1. 复用各功能已有的世界、光照、形状和红石入口，不添加组合专用产品逻辑。
2. 玩家继续使用配方、右键放置、长按采集和暂停菜单，不增加操作或设置。
3. 地毯的透光、侦测器的完整盒体与草变更通知均由现有实际状态推导。
4. 验收直接调用真实 World/VoxelLight/Redstone，并跑正常玩家输入；不替换内部模块或读取源码断言。
5. 覆盖全部地毯颜色、源和目标草地、两种草变更及卸载，避免单一演示位置专用实现。

## 先列出的组合失败类别

- 地毯的完整碰撞底面误杀草，或阻止草传播到其下方；完整侦测器反而被当成透光薄块。
- 草传播与覆盖退化漏发侦测器更新，等值重写或卸载编辑反复产生假脉冲。
- 实际玩家铺毯、挖毯、放完整机器后，维护顺序、光照 revision 或支撑逻辑使结果与单独模块不同。
- 暂停/恢复和真实卸载/返回失效，Continue 丢失草、地毯、机器或库存。
- 合并后的地毯、侦测器 UI 流程或已有彩色体积光发生回归，生产构建暴露开发 fixture。

## 整合后的设计复查

持续时钟会让原维护调用总撞上过期光场，因而补上共享 `Graphics.updateVoxelLight(dt, force)` 入口，将既有刷新、体积上传和地形重照一起复用。正常渲染与每秒维护是两个真实调用方；仅脏或过期时多一次加载体积刷新，其成本与加载单元数成比例，没有按草采样重复计算。只调用强刷而不发布的尝试会吞掉渲染回执，该失败也已保留，最终实现不使用 dirty 补偿或第二套状态。

全部产品、测试和文档的新增/修改行已逐行检查。`setState(..., record=false)` 供正常碰撞试探使用；草的面积辅助函数测量现有形状；地毯复用 tile、染料与羊毛；侦测器复用八向 facing、powered 和现有计时。没有新增玩家参数、依赖、存档字段、兼容格式或测试专用产品分支。独立功能的边界见各自验证文档，原版完整更新顺序、地毯燃料/骆马装饰、完整动物寻路仍未实现。

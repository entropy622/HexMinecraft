# 玻璃日月透射验证（0.80）

## 实施前判断

1. 结构：让真实玻璃的光路长度改变 RGB 直射光，复用六棱光照体积与日月阴影；不会用地面染色代替光照。
2. 负担：不新增玩家设置、存档字段、依赖或渲染目标；仅光影档执行玻璃光路积分。
3. 可推导：玻璃范围来自实际已加载世界，光路来自实际日月方向，吸收色与不透明度来自已有玻璃材质定义。
4. 复杂度：复用树叶已有的六棱边界步进，光线先与实际玻璃包围盒相交，仅遍历可能经过玻璃的区段；不建立通用透明材质或深度剥离框架。
5. 泛化：覆盖单层 / 叠层 / 斜射 / 日月 / 移除 / 负坐标，静态建筑与动态实体使用同一接收路径；不透明几何继续由真实阴影负责遮挡。

最小实现是在现有光照体积空余的介质码中识别玻璃，按逐格实际光程积分吸收。仅增加固定玻璃色或单张最近透明深度不能表达叠层和斜射厚度；为本项目现有一种琥珀玻璃增加额外颜色渲染目标也没有必要。玻璃图案的基色应与物品定义一致，边框保留像素高光。

参考 Photon 固定提交 `6e67b36e818bacde0304edd49f28e2bb70e33f04` 的[透明阴影颜色](https://github.com/sixthsurge/photon/blob/6e67b36e818bacde0304edd49f28e2bb70e33f04/shaders/program/shadow.fsh)和[透明 / 不透明阴影组合](https://github.com/sixthsurge/photon/blob/6e67b36e818bacde0304edd49f28e2bb70e33f04/shaders/include/lighting/shadows/pcss.glsl)。借鉴分离透射颜色与不透明可见性的思想，独立实现六棱体积积分，不打包上游代码。

## 实施前失败类别

- 玻璃只在屏幕上半透明，地面直射项没有颜色；只乘灰度或对环境光 / 发光方块整体染色。
- 多层与一层相同、斜射没有更长光程，或面邻接时多算 / 漏算；负坐标或轴平行光线除零。
- 石墙、薄建筑或叶子被误认为玻璃；玻璃背后有不透明屋顶仍透光；改变玻璃后旧色残留。
- 月光、阴影范围外、下界 / 末地或低画质错误发光；玻璃包围盒为空或光线没有穿过时仍改变画面。
- 步进越出已加载体积、跨区块或极低角度耗尽步数；测试仅比较整张截图而没有分离直射和环境项。
- 材质外观与吸收色不一致；画质 / 大小 / 上下文恢复 / 水面捕获破坏已有树叶、水下光或设备资源。
- 验证触发原生 Pointer Lock 或操作前台鼠标。

## 结果

实施前通过真实世界、现有光影档和配对线性渲染复现：单层 / 三层玻璃的直射 RGB 比例均为 `[1, 1, 1]`，石屋顶则为零。`before.log` / `before/` 保存失败；没有以源码文本或替代着色器证明缺口。

首轮玩家检查通过。单层日光约保留 `[0.930, 0.820, 0.664]`，三层约 `[0.804, 0.553, 0.294]`；拆除后恢复 `[1, 1, 1]`，完整石块与半砖屋顶将直射项挡至零。单层 / 三层的环境项与无玻璃相同。

三项新场景均有通过记录（`three-player.log` / `three-player/`）。负坐标斜射约 `[0.889, 0.726, 0.516]`，光程比日间更长；月光约 `[0.933, 0.828, 0.678]`，原生 Continue 后比例相同。画质开关符合既有档位，WebGL 恢复后的直射比值为 `[1, 1, 1]`，页面 / GL 错误为零。实际 UI 从快捷栏选择并放置琥珀玻璃，未调用开发 API。

`npm run check`：106 / 106 逻辑检查与 0.80.0 构建通过，保留已有大 bundle 提示。最终相关图形回归 10 / 10 通过（`regression.log` / `regression/`），包括水下焦散、层级 / 实例化生物受光、四项树叶透射 / 遮挡 / 日月云影 / 水面与设备恢复、带天窗建筑的新玻璃恢复场景、实际界面，以及两项日月软阴影 / 材质恢复。新玻璃恢复场景与三项新场景有重叠，不重复相加为独立覆盖。

差异复核后扩展既有树叶场景，增加实际玻璃位于光源与叶片之间时的逐通道透射比例，防止仅保留灰度衰减。`leaf-tint.log` / `leaf-tint/` 通过，943 个叶片采样像素的 RGB 比例约为 `[0.930, 0.821, 0.665]`，厚树冠 / 石屋顶 / 恢复与覆盖断言全部保留。该扩展未增加产品入口或新的测试文件。

正式构建的实际 UI 1 / 1 通过（`production.log` / `production/`）：在光影档通过实际输入选择并放置玻璃，目标识别为琥珀玻璃，页面与 GL 错误为零。记录 `developmentFixture: false`，未调用开发接口；已查看正式构建的实际放置截图。

所有检查使用后台无头 Chrome 与设备边界的原生 Pointer Lock 替代，独立开发端口 5174 / Vite 缓存和正式预览 5176；未操作前台鼠标或用户的 5173 页面。截图包括线性控制场景、正常光影档，以及实际建筑的玻璃天窗 / 开放天窗对照；其意义是局部光学验证，尚非全世界美术或硬件性能验收。

## 范围与限制

- 当前是一种既有琥珀玻璃的几何体积吸收，未引入十六色染色玻璃、染料配方或可调吸收参数。
- 只滤日月直射与树叶的该光源透射项；环境天空光、发光物体和雾中的光束尚未加入玻璃颜色。不声称已完成 Photon 的完整彩色光传输。
- 使用直线光路与均匀的每单位长度吸收；玻璃表面的 Fresnel、色散和玻璃 / 水的联合折射尚未实现。水下已有焦散、吸收与折射继续独立工作。
- 玻璃的色彩轮廓来自六棱体积，未按可见日月盘做额外透明半影积分；不透明物体继续使用已有 PCSS。像素边框只属于表面图案，没有单独的不透明边框阴影。
- 范围只包含实际已加载玻璃，随既有光照更新刷新；光线最多跨 256 个单元面，受既有加载范围约束。未增加远处未加载玻璃的光传播或全场景光线追踪。
- 未增加保存版本、资源依赖或渲染目标；本轮未扩展生物 / 群系 / 地下内容，完整 MC 与 Photon 持续目标仍未完成。

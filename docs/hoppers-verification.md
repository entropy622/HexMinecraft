# 漏斗与自动运输验证（0.66）

## 实现前的范围判断

1. 结构：把手动容器槽位与自动运输接到同一套取放规则，覆盖箱子、漏斗、熔炉和酿造台。
2. 负担：玩家只选择放置方向和红石开关；容量、接收面、冷却与堆叠上限由系统决定。
3. 可推导：以实际目标方块、方向和槽位内容推导运输结果，不增加过滤模式、运输配置或独立库存副本。
4. 复杂度：复用 World 的储物表、已加载红石索引、固定步进及现有物品取放端点；只增加实际漏斗模拟与实体拾取入口。
5. 泛化：处理所有现有储物容器和三种熔炉，保留工具、附魔、命名和潜影盒内容，而非只支持石头运输演示。

最小完整改动是五格漏斗、朝下或六向侧面出口、0.4 秒运输间隔、上方输入、实体吸入、通电停机、可操作 UI 与存档。只加模型或直接改物品数量无法提供可玩的自动运输；另建一套容器规则会让手动和自动取放逐渐分叉。冷却单独存储，因为每帧写方块状态会无谓重建光照与碰撞缓存。

规则对照：[Cuberite 漏斗接口](https://github.com/cuberite/cuberite/blob/master/src/BlockEntities/HopperEntity.h)及[实际运输实现](https://github.com/cuberite/cuberite/blob/master/src/BlockEntities/HopperEntity.cpp)。本项目保留自己的六边形几何和固定步进，不声称逐刻复刻 Java 版更新优先级。

## 实现前列出的失败类别

- 放置：顶面、底面应朝下；侧面指向被点击方块；不能朝上；无支撑仍保留；与玩家及实体碰撞不能强行放置。
- 运输：每次最多推一件、再从上方拉一件；不足 0.4 秒不能再次工作；阻塞和空来源不扣物品；同帧不能穿过整条空管线；闭环无复制或丢失。
- 槽位：优先合并可叠物品；遵守 64、16、1 的容量；满目标不消耗来源；工具磨损、附魔、命名和潜影盒内容完整保留；禁止潜影盒嵌套。
- 接收面：熔炉顶面仅原料、侧面仅燃料、底部仅成品或空桶；酿造台顶面原料、侧面药水或燃料、底部药水；不偷走未用燃料或原料。
- 熔炉经验：自动取出不向玩家发经验，不清空累积经验；大量自动烧炼后的经验可保存，再由手动取出或拆除领取。
- 红石：实际线路锁定后停止自身推、拉、吸入；外部漏斗仍可向被锁漏斗插入；比较器按五格容量读取，盖住漏斗不误判为盖住箱子。
- 实体：只吸实际口部与上方范围内可到达的物品；墙和完整顶盖阻隔；大堆实体只扣成功接收部分，工具实体逐件保留元数据，消耗后无残留模型。
- UI：五格显示、左右键、Shift 快移和触屏操作使用已有库存会话；自动变化实时显示，不能每帧重建按钮打断拖拽。
- 生命周期：拆除和爆炸各掉落一次内容；暂停及隐藏页面停止，容器界面继续；未加载区块与其他维度冻结；恢复后不补离线时间。
- 存档：实际五格内容、出口及剩余冷却恢复；没有可选冷却表的现有 v16 仍可读取；错误容量、非漏斗计时、重复键、负值、非数值和超限计时拒绝。

## 范围与实现限制

- 出口与碰撞是六棱世界版本，按坐标稳定排序并限制每步可抽出的初始库存；不复刻 Java 版的所有更新优先级。单个大堆散落实体可一次填满剩余容量，容器之间仍每周期一件。
- 酿造自动化沿用现有药水类型与配方；底部会抽水瓶，需要玩家用红石安排酿造等待。尚无空玻璃瓶槽、漏斗矿车、含水漏斗、自动过滤配置或批量工业装置性能验收。
- 炉具浏览器场景从合法的 9.8 秒烧炼进度恢复以缩短软件渲染时间；完整加工和计时算法另由逻辑测试执行。酿造台接收面、重置批次及三种炉具细分规则本轮由逻辑测试覆盖，没有分别跑浏览器完整酿造与三种炉具 UI。
- 拆除已走真实挖掘验证；爆炸复用同一 `removeBuilding` 库存散落路径，本轮未额外引爆。页面隐藏暂停也未单独触发；普通菜单暂停由现有容器 / 红石回归覆盖，未加载区域冻结由逻辑检查覆盖。
- 本轮没有扩展 Photon 算法或新增外部素材，模型继续使用现有体素光与材质渲染路径。截图属于无头 Chrome 软件渲染验证，未进行用户显卡性能验收。

## 交付后的设计检查

手动 UI、自动运输和比较器共同读取 `blockSlots`；删除主入口和比较器中重复的炉具 / 酿造槽规则。容量来自方块定义，储物仍只有 `World.chests` 一份；没有第二套漏斗物品表、新玩家配置、依赖、贴图文件或测试专用产品开关。

新增 `down` 与已有 `facing` 合起来表达七种真实出口，邻居被移走后仍需保存该选择；`mount` 专门表示控制元件的支撑面并允许天花板，漏斗不要求附着，故未混用。冷却由模拟器持有并存档，避免每帧写形状状态触发光照 / 碰撞失效。几何模块仅定义实形，经已有 `buildingParts` 入口共同供渲染、碰撞、手持模型与图标使用；没有另设形状框架。可选冷却表缺省为空，沿用同一个 v16 解析器，没有旧格式迁移或双重读取路径。

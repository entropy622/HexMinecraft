# 分支与循环中的阴影缓冲采样

## 编码前的设计判断

1. 结构性：原始阴影深度与接触遮蔽合成读取的是无 mip 的渲染缓冲，分支/循环中应明确读取第零级，避免依赖片元导数。
2. 调用负担：不增加设置、参数、纹理、目标或存档字段。
3. 可推导性：缓冲只有第零级，采样级别由资源事实确定，不交给玩家选择。
4. 最小性：只修改实际取证涉及的原始阴影深度与接触遮蔽合成采样，保留材质贴图的正常 mip 过滤；不修改依赖、屏蔽日志或另加渲染分支。
5. 泛化：所有使用这些真实缓冲的阴影接收面和深度合成都适用，不按模型或截图位置特判。

最小修正是对无 mip 的这些采样使用显式 LOD 0。现有采样的过滤与比较逻辑不变，材质贴图仍使用正常导数选级；单纯关闭编译日志不能修正着色器执行契约。

## 修改前的实际证据与失败类别

0.84 `9f98362` 在 headless Chrome / 实际 RTX 4060 ANGLE D3D11 上，空气与水下光影场景均产生 X3595。只读拦截设备 `getProgramInfoLog`、查询 attached shader 的 GLSL 与 `WEBGL_debug_shaders` HLSL，取得 13 份含警告的程序日志；没有替换或更改编译输入。HLSL 的隐式 `gl_texture2D` 调用 D3D `Sample`，相关接收面含 PCSS 循环，接触遮蔽合成含深度条件后的采样。这些资源没有 mip；此处选择 LOD 0 对应原有资源契约。

原始行号经过 ANGLE 注入，不能直接当作仓库行号。完整原始 GLSL、翻译文本、警告、实际 renderer 和 GL 0 记录在 `C:/Users/aentrozhou/.codex/artifacts/hexminecraft-round-0.85/shader-warning-original.json` 与 `shader-warning-translated.json`；两轮专属服务器和浏览器均确认退出。

先列出的失败类别如下。

- 实际高画质接收面或接触遮蔽仍产生依赖未定义导数的采样警告，或者以屏蔽日志掩盖问题。
- 改动误伤材质 mip 过滤、改变原始深度比较、接收面校正、半影宽度或彩色玻璃透光。
- 普通画质阴影、真实水面/建筑/生物材质、resize 和上下文恢复发生回归。
- 只检查 GLSL 字符串却没有编译真实场景，或只有无警告而没有有效 HDR 读回与实际图像。

在已有 `tests/soft-shadows.spec.js` 的真实场景与 HDR 读回上增加驱动场景，复用现有场景入口，不复制渲染算法。测试明确重新启用 `occlusion=0.6`，验证实际接触遮蔽通道开启，避免场景准备时关闭它而遗漏对应程序。

## 红绿证据与相关回归

新增硬件场景先在隐式采样版本运行：GL 0、有效非零 HDR、原始无比较阴影深度和无 mip 缓冲、实际启用的接触遮蔽及错误为空的断言均通过，最后精确失败于 **13 条 X3595**。修正后同一场景通过，警告 **0**、错误 `[]`、GL 0；实际设备两次均为 RTX 4060 / ANGLE D3D11。401 个固定直接光 HDR 扫描点的最大绝对差与 RMS 均为 **0**。该比较覆盖场景的直接光扫描；接触遮蔽另由实际编译/开启、全场景图像和生命周期回归覆盖。

只将 `softShadowDepth` 的一次底层读取和接触合成的四种输入改为 `textureLod(...,0.0)`，并将材质程序缓存键更新为 v6。阴影深度/AO/protection 为无 mip 的 Nearest 资源，sceneColor 为无 mip 的 Linear 资源，各自 min/mag 过滤一致。LOD 0 保留过滤、手工深度比较、反向深度与接收面校正。正常材质 atlas 的 mip 读取、导数斜率修正、Balanced 的 Three PCF、采样数量与依赖均保留。

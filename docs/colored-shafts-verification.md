# 彩色体积光验证（0.83）

## 实施前判断

1. 结构：把玻璃已有的逐格 RGB 光程吸收接入空气和水下体积散射，让表面和雾中采样使用同一规则。
2. 负担：沿用光影档、日月方向、实际 World 和已加载光照体积，不增加玩家设置、存档字段、渲染目标或依赖。
3. 可推导：颜色与消光系数取实际玻璃调色板，边界由现有上传过程测量，采样起点取体积光实际世界坐标。
4. 复杂度：抽出表面已使用的有界六棱吸收积分及其共享材质系数；不增加第二张颜色体积、透明阴影图或玻璃专用后处理通道。
5. 泛化：覆盖红蓝、白黑、叠层 / 顺序、日月 / 斜射、真实不透明屋顶、移除、保存 / 维度 / 画质 / 设备恢复及水下散射。

最小完整改动是在现有体积光的日月源项乘以真实玻璃光程的 RGB 透射，而天空环境、局部发光和视线方向消光保持各自物理含义。仅对最终画面染色或把灰度阴影替换为固定颜色，无法区分光线是否真正穿过玻璃，也会污染局部光和环境项。

参考 Photon 固定提交 `6e67b36e818bacde0304edd49f28e2bb70e33f04` 的[空气雾逐步散射](https://github.com/sixthsurge/photon/blob/6e67b36e818bacde0304edd49f28e2bb70e33f04/shaders/include/fog/overworld/raymarched.glsl)及[透明 / 不透明阴影组合](https://github.com/sixthsurge/photon/blob/6e67b36e818bacde0304edd49f28e2bb70e33f04/shaders/include/lighting/shadows/pcss.glsl)。2026-10-28 读取固定提交源文件，借鉴分离颜色与可见性后积分散射的思路，独立接入本项目的六棱光照体积，不复制或打包上游实现。

## 实施前失败类别

- 表面已滤色但雾中日月项仍为白色；空气路径生效而水下路径不生效，或错误染整张画面 / 视线消光 / 天空环境和火把散射。
- 单层与叠层相同、异色顺序产生无依据差异、斜射没有更长光程；白色过暗、黑玻璃发光、空世界或未经过玻璃也染色。
- 石屋顶、半砖等真实不透明几何后仍有彩色日月束；局部光被错误阻断或染色；太阳 / 月亮或负坐标越界。
- 放置 / 拆除、区块上传、保存继续、维度往返保留旧颜色；光影 / 均衡 / 流畅切换、大小或上下文恢复后失效 / GL 错误。
- 抽出共享积分破坏既有表面 / 树叶滤光或高位材质索引解码；重复系数、未读取数据或仅测试使用的产品入口。
- 无玻璃仍遍历全体积、已被不透明阴影挡住仍作吸收积分，或新增不可释放的 GPU 资源。
- 后台检查调用原生 Pointer Lock 或接管前台鼠标。

先通过实际 World、光影档和实际 AtmospherePass 的 HDR 输出，比较有无日月源项的 RGB 散射，保存失败结果后再实现。测试沿用原生 Pointer Lock 的设备边界替代，使用独立端口 5174 / 5176，不操作用户的 5173 页面。

## 结果与边界

实施前的真实体积输出中，红 / 蓝 / 白 / 黑和叠层玻璃的日光 RGB 比例均约为 `[1, 1, 1]`，石块与半砖为零，复现“灰度遮挡正常但体积光无玻璃颜色”。`before.log` 和 `before/` 保留原失败。第一轮夹具曾误用不存在的玻璃 ID，修正为实际 `StainedGlass` ID 并清理原生水体后才取得上述有效失败；该夹具错误不算产品缺口。

最终 `npm run check` 通过 125 项逻辑检查（123 项原有和两项距离上传检查）和 0.83.0 生产构建，保留已有的大 bundle 提示。新增行为由五个实际浏览器场景覆盖，没有为着色器增加源码文本断言或替代着色器。

- 空气体积：红玻璃 RGB 比例约 `[0.746, 0.572, 0.569]`，蓝玻璃约 `[0.579, 0.585, 0.732]`；三层红约 `[0.415, 0.187, 0.184]`。红蓝 / 蓝红交换的逐通道最大差约 0.00016；白玻璃保留接近完整光，黑玻璃各通道衰减。石块与半砖屋顶为零，拆除恢复约 `[1, 1, 1]`。红蓝的环境散射和视线消光保持相同。
- 实际占据水体：一层蓝玻璃约 `[0.580, 0.585, 0.732]`，三层约 `[0.195, 0.200, 0.392]`，石屋顶为零。局部火把提高自身散射，切换蓝 / 红玻璃不改变其环境项；玻璃叠层不改变视线穿水长度。最终夹具另为火把补上实际石块支撑，保留全部原有断言。
- 负坐标与恢复：斜射蓝玻璃约 `[0.384, 0.389, 0.560]`，月光约 `[0.595, 0.600, 0.743]`；原生 Continue 后一致。均衡 / 流畅无体积 Pass 且玻璃光影开关关闭，光影档恢复。大小改变与 WebGL 上下文恢复后日光比例为 `[1, 1, 1]`，下界无日月源，主世界往返误差小于 0.001。页面和 GL 错误为零。
- 生产 UI：5176 预览从实际原生导出构建房间输入，经真实导入分别显示琥珀 / 石屋顶 / 蓝色天窗；实际相对鼠标事件放置一块蓝玻璃，再导出确认由八块增加到九块，创造库存仍为 64。记录 `developmentFixture: false`、GL 错误 0、页面 / 控制台错误为空。已查看三组房屋截图及空气、水下和恢复截图。

上述量化读回使用游戏实际 AtmospherePass 和实际光照 / 阴影，配对关闭已有日月物理源项来分离太阳散射，alpha 独立检查视线消光；没有替换 World、光照输运、体积着色器或生产组合。房间在正常完整光影档渲染，天窗光束可见；蓝 / 琥珀的整幅画面色差较克制，天空环境仍占相当比例，不以整个画面染色作为验收。它们是局部光学与建造证据，并非完整 Photon 美术对等。

RTX 4060 / D3D11 的 12 项相关图形场景已取得通过证据（首批 11 项通过，修正跨维度比较的密度就绪后两项定向复测通过，包含重复的十七色契约场景）。扩展实际 GPU 解码到空气和火把单元，确认 B 高位距离存在时 RGB 低位仍与 CPU 相等。最终生产 UI 在 RTX 4060 / D3D11 再次通过，`developmentFixture: false`、GL 0、蓝玻璃八块变九块、创造库存 64。最终 SwiftShader 定向复测 5 / 5 通过（12.0 分钟），包括远玻璃、空气、水体、原生 Continue / 恢复长流程，以及十七色和高低位解码。全部证据合计 13 个独立浏览器场景；定向重复不重复计算。

硬件首轮跨维度对比的约 8% 差异来自比较尚在过渡的实际雾密度：就绪复测记录返回初值 0.0085845，而比较前为 0.0079995；等待实际密度稳定后为 0.0080013，RGB 比例恢复约 `[1.00020, 1.00005, 1.00003]`，原 4% 阈值保留。测试现在观察实际密度稳定，不用少量快速硬件帧冒充足够长的物理过渡。

上一版独立副本中，相同长流程仍在原预算内通过；软件下的远玻璃对照三次绘制 / 读回约 1387 / 2302 ms。两项长流程的累计预算调整为 480 / 600 秒，逐次 60 秒就绪限制和全部数值断言未变。该调整仅覆盖串行读回、原生重载及画质 / 设备重建的累计时间；产品仍采用相同精度的空域优化。首批超时、旧版对照和后续结果分别保留，不把未完成场景计为通过。

## 设计复查与限制

### 稀疏玻璃的空域跳步（实施前）

首批相关回归 7 项通过，两项长流程分别耗尽 240 / 360 秒总时限。进一步用实际体积 Pass 构造光束之外的两块远处玻璃，散射比例仍为 1，但同样三次绘制 / 读回由约 2190 ms 增至 5226 ms（SwiftShader）。全局玻璃包围盒会覆盖大量空单元，逐步体积采样重复遍历这些空域；这应从光学寻址本身处理，而不减少体积步数、降低颜色精度或放宽已有数值断言。

1. 结构：对任何颜色和稀疏分布记录保守空域距离，跳过确定没有玻璃的光程，仍精确积分实际玻璃段。
2. 负担：在既有 DynamicLight 上传中推导，不新增玩家选项、调用参数或保存字段。
3. 可推导：种子来自实际玻璃介质码，距离由当前已加载光照网格计算；移除 / 重传时重算，无额外持久状态。
4. 复杂度：利用现有 RGBA8 的 B 高四位存距离下界，不添加纹理、渲染目标或第二种光学路径。
5. 泛化：覆盖空场、单块 / 多块、边界、负坐标、所有玻璃色、轴平行与斜射、更新 / 移除和原有 RGB 低位解码。

数值失败类别先列为：无玻璃保留旧值；种子非零；邻接跨 y / r / q 边界串行绕回；多种子不取最小距离；远场溢出四位；距离高位污染低位发光；移除后不清除；跳步跨过玻璃或漏算薄层 / 斜射。采用六邻 Manhattan 距离的双向扫描并将距离截断到最多 45，`ceil(distance / 3)` 是三轴 Chebyshev 格距的下界；若下界至少为 2，减一格是保守世界距离。六棱 q / r 坐标的梯度范数为 2/3，单格偏移不超过 2/3，因此该跳步不会越过另一玻璃棱柱（保留原有 0.002 面偏移容差）。仅空单元使用跳步，玻璃内部仍逐面计算光程。

产品改动逐行复查范围为 `atmosphere-pass.js`、`dynamic-light.js`、`glass-transmission.js`、`light-volume-shader.js`、`soft-shadows.js` 与 `main.js` 的版本 / 已有画质说明；同时复查新增测试、扩展的 GPU 解码场景、README、开发状态和版本配置。原玻璃积分从 SoftShadows 抽出，表面法线偏移仍在表面调用处，体积从实际空气 / 水体采样点出发。原消光系数移到已有共享光照 uniforms，只保留一份数据，两个着色器消费者通过同一入口使用，没有新增调用参数、用户选项或单调用者框架。

没有增加纹理、渲染目标、存档字段、依赖或保存版本。空玻璃边界或光线不经过包围盒时立即返回；已被实际不透明阴影挡住时不执行玻璃积分。沿用最多 256 次六棱面穿越、既有半分辨率体积采样和四通道输出。

玻璃吸收仍为已加载六棱体积中的直线光路，未联合追踪玻璃 / 水界面的折射、色散或多次散射。玻璃边框没有独立不透明阴影，透明色边界未增加日月盘的半影积分；并非所有材质 / 群系 / 地下环境已作美术验收。宽范围玻璃会增加逐步体积积分开销，无玻璃场景有提前返回；实际 GPU 已补充正确性与三次绘制 / 读回的诊断延迟，仍不能据此推断完整游戏帧率；D3D11 存在梯度在变动循环中的编译警告，页面 / GL 错误为零，但未宣称所有驱动警告已清理。整体 MC / Photon 开发目标仍在推进。

证据位于工作区外 `colored-shafts-0.83` 目录，包括实施前失败、四项新图形场景、生产构建 / UI、相关回归、语义 JSON、截图和最终源文件 / 构建指纹。所有浏览器使用后台 headless Chrome（SwiftShader / D3D11）及现有 Pointer Lock 设备边界夹具，未操作前台鼠标或用户 5173 页面。

最终空域诊断：SwiftShader 的三次真实体积绘制 / 读回由优化前裸场 2190 ms、远玻璃 5226 ms，变为优化后裸场 1523 ms、远玻璃 1770 ms；相对裸场由 2.39 倍降至 1.16 倍，光学比例仍为 1。RTX 4060 / D3D11 对应约 12.54 / 14.85 ms。这些是单场景诊断观测，包含同步读回及驱动 / 传输开销，不能换算为整游戏 FPS。两项新增 Node 检查通过独立穷举最近距离和实际几何射线检查距离下界、轴边界、负坐标、四位饱和、RGB / 天空光保留及移除重传。

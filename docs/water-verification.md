# 0.57 水面光学验证

设计阶段基于 `e679001`，日期 2026-10-26。

## 实施前的设计检查

1. 结构上从当前帧场景颜色与深度求交，适用于所有高度的已加载水面，不依赖单一海平面。
2. 沿用「光影」画质档，玩家不必填写反射目标、水平面或水深参数。
3. 表面位置、波浪法线、透射厚度、前景遮挡与屏幕边缘由实际几何和深度推导。
4. 最小实现扩展既有水材质和场景帧捕获；不另建通用反射框架或增加依赖。Three.js 的 SSRPass 已检查，但其全场景法线 / 金属度渲染不能直接替代透明水的分层合成，因此只实现水材质缺少的部分。
5. 使用河湖、玩家水池和不同高度表面验证，避免仅服务一个截图。低档和水下沿用原路径；本轮先实现水面外侧的场景反射与折射。

反射不能只调整原来的天空混色，因为那条路径没有周围建筑和生物的颜色 / 深度。光影档先捕获去掉水与手持模型的场景，再让水材质采样独立目标，避免读写同一纹理。参考 Photon 的深度求交、命中细化、边缘衰减和折射前景拒绝思路，独立实现本引擎所需的当前帧版本。

## 实施前列出的失败场景

- 建筑改变颜色，倒影不变；只镜像天空而未命中实际场景。
- 水体或第一人称手臂反射自己；取样正在写入的目标。
- 深度跃变、离屏或掠射反射产生拉长条纹与错误命中。
- 折射采到水面前方的岸边；浅水和深水完全同色。
- 多个水位、流水或水下视角出现 NaN、黑块或穿透。
- 关闭光影、窗口缩放、维度切换后使用失效纹理；没有可见水仍持续重复渲染场景。

## 实现与观察

水材质进行最多 32 次深度采样和 5 次命中细化。捕获使用独立的 HDR 颜色 / 深度目标，不采样正在写入的目标；手持模型和水体本身从捕获中移除，再恢复可见状态。已有物理水面不位移，法线扰动减小，并限制反射方向位于几何水面上方。高光乘入菲涅耳响应，避免俯视水面时出现过强白斑。

新增运行时数据只用于真实渲染：颜色 / 深度纹理、相机投影与逆投影、分辨率、捕获是否可用，以及从玩家所在液体推导的水下状态。采样前景、厚度、边缘和近裁面均从相机 / 深度推导；没有新的玩家配置或存档字段。复用 Three.js 的 RenderPass、现有场景帧和水网格，未新增框架或依赖。

建筑颜色对照在修改前先复现：固定相机、水面和时间，红色塔楼变为青色后，水面 HDR 采样完全不变，RGB 差为 0。实现后的同一场景 RGB 差约为 0.066；截图同时保留塔楼本体和倒影，排除仅使用天空颜色的情况。取样等待完整渲染帧，并从生产 `fluidHeight()` 推导表面位置，避免使用未更新的相机矩阵或越界读回。

水深检查通过替换两处实际池底材质，比较池底颜色变化传到水面的强度，排除反射、散射、高光和不同水深的池底照明差异。本轮浅 / 深水响应分别约为红色 0.535 / 0.147、绿色 0.786 / 0.487、蓝色 0.865 / 0.644，深水对红光变化抑制更多。预期值没有从生产吸收系数计算；检查读取实际捕获目标和水面图像。由于斜视射线在深池底部偏移更远，替换区域覆盖实际可见的池底，而非只改水面点正下方的一格。

视口缩放检查捕获目标与采样分辨率同步，低档切换检查 Three.js 目标确实释放，水下和朝向不含水网格的视锥时停止捕获。渲染继续使用后台无界面的浏览器，Pointer Lock 只在浏览器设备边界模拟，不控制前台鼠标。

## 适用范围与限制

额外成本为视锥内有水且相机不在液体中时的一次场景捕获、一个全分辨率 HDR / 深度目标及水面像素上的求交。视锥裁剪不等于遮挡查询，墙后仍在视锥内的水可能触发捕获。本轮没有提供真实硬件 GPU 耗时或帧率结论。

反射依赖当前画面及深度，没有屏幕外物体、另一层透明表面或隐藏面的信息；边缘会淡出到天空近似。没有时域积累，细小目标与遮挡边缘仍可能闪烁；反射雾的路径与 Photon 的处理不完全相同。折射使用屏幕位移和深度拒绝，厚度来自水面后方的可见表面，没有完整水下光线追踪。本轮不包含焦散、几何波浪、水下全反射或 MC / Photon 对等验收。

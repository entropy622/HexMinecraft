# 巨型树种植与生长

0.122 加入四株同种丛林/云杉树苗共同长成巨型树的玩法。总体 MC/Photon 目标尚未完成，森林参考图、高处树叶亮度与远景仍需改善。

## 玩家操作

把四株同种树苗排成相邻菱形，支持六边形网格的三种方向。任一株自然成熟或使用骨粉，都能触发整组生长。完整树阵空间不足时四株保留，不回退成单株树；成功才消耗骨粉，并同时移除四株树苗。数量不足或混种仍按原来的单株行为处理。准星与交互提示说明成组规则和受阻原因。

丛林巨树采用 10～31 格树干、粗树干、分层主冠和伸出的侧枝冠；云杉巨树采用 13～29 格树干及长冠/短冠两种形态。三根副干在树顶短一格，横枝保留真实原木朝向。生成的是现有材质的实际方块，沿用采集、去皮、木作、可可支撑与叶片支撑/掉落系统。树形以种子和根位置确定，六边形枝冠是宿主适配。

仅在全部土壤、生长方块、加载状态、液体、占位实体和其他作物检查通过后才提交。保留对玩家放置树叶的既有保护，允许原木替换自然树叶。沿用现有成熟时长、骨粉成功消耗规则和 v16 存档，没有新增生长时钟、巨树方块类型或资源文件。

当前巨树通过种植获得。自然群系的巨树分布、藤蔓、灰化土装饰尚未加入；自然普通树的布局函数保持不变。新增截图使用玩家建造的种植台，不表示已有自然巨树林群系。

## 规则来源

基础规则参考 [Mojang 树苗说明](https://www.minecraft.net/en-us/article/taking-inventory--sapling)。四株检测、失败恢复以及粗树干结构另外静态核对 Java 1.21.5 官方 [server.jar](https://piston-data.mojang.com/v1/objects/e6ec2f64e6080b9b5d9b471b291c33cc7f509733/server.jar)，SHA-1 `e6ec2f64e6080b9b5d9b471b291c33cc7f509733`，以及 [官方 mappings](https://piston-data.mojang.com/v1/objects/f4812c1d66d0098a94616b19c21829e591d0af3a/server.txt)。

`TreeGrower` 对应 `ebe`，生长方法源行 92～144：找到完整 2×2 后尝试巨型 feature，失败恢复四株并直接返回失败。`GiantTrunkPlacer` 对应 `eqg`，顶层只留主干；`MegaJungleTrunkPlacer` 对应 `eqh`，侧枝位于较低高度并提供独立枝冠附件。官方 `mega_jungle_tree` 配置为 base10/rand2/rand19；`mega_spruce`、`mega_pine` 为 base13/rand2/rand14，冠层深度分别 13～17 / 3～7。静态观察来自已安装 JDK 的 javap，并提取官方配置核对；未执行 Minecraft JAR。

官方 JAR、映射、配置和反汇编仅存在外部证据目录，这些文件及原游戏资产未提交到仓库。几何布局由本项目按六边形连接关系实现；不声称方块坐标、Java 随机刻或装饰完全一致。

## 验证与画面

18 项相关 Node 检查通过，覆盖四株在各方向/各触发角的一致识别、混种/缺株、真实连通树干、六格内叶片支撑、树高范围、两种云杉冠层、原木轴向、土壤/液体/实体/未加载/高度/其他作物阻挡，以及真实世界 v16 编辑和枝干朝向的恢复。普通树、天然树跨区块和丛林可可相关检查继续通过。

两项开发浏览器检查通过。巨树场景通过原有种植/交互路径种下四株并消耗四份树苗，阻挡时保留四株和四份骨粉，成功后只消耗一份骨粉；两种方向的丛林树与另一方向的云杉均生成实际方块。云杉预置一株成熟年龄后推进正常游戏维护，验证自然成熟触发且不消耗骨粉，不把它当作完整等待时间/随机刻分布验证。另一项检查保留普通橡树生长和固定森林镜头。

实际巨树导出经生产 UI 导入/导出，全部世界编辑、枝干朝向、位置、时间逐项一致，生产开发 API 不存在。沿用 v16；已有普通存档不需要迁移。构建、改动文件格式及差异检查通过。

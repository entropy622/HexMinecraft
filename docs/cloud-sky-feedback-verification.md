# 云环境图、天光与反射

0.113 已加入 [天空环境雾](sky-fog-verification.md)。当前 SH 与环境天空反射包含空气，低档保留雾环境图，归约目标为 20×1；下文描述 0.111 当时的云环境实现与资源状态。

0.111 补齐真实云层进入环境天空图的路径。此前可见云和地面云影存在，但 SH 及天空反射仍只看到晴空散射，林冠暗面缺少天空中云的颜色和照明关系。整体 MC/Photon 目标、参考图及完整天空仍未完成。

## 来源与接入

只读 Photon `6e67b36e818bacde0304edd49f28e2bb70e33f04` 的 [d0_sky_map.fsh](https://github.com/sixthsurge/photon/blob/6e67b36e818bacde0304edd49f28e2bb70e33f04/shaders/program/d0_sky_map.fsh) 调用 [sky.glsl](https://github.com/sixthsurge/photon/blob/6e67b36e818bacde0304edd49f28e2bb70e33f04/shaders/include/sky/sky.glsl) 的 `draw_sky`，先按透射与散射合成真实云，再投影环境光和采样天空反射。源还合成解析雾、极光和曙暮光线，本批尚未接通这些分支。

现将既有视图云积分移入 `cloud-integral.js`，保留三层真实密度、上下层遮光、多次散射近似、空气输运、早停和视图距离/历史元数据。可见云继续走原视图深度与历史；新的 96×48 全天空捕获调用同一积分，没有用覆盖率均值或固定白色替代真实云。

`skyRadianceMap` 仍是可见背景和云空气输运所需的晴空；`skyEnvironmentMap` 是含云环境图，供 SH 和天空反射读取。保持两个输入可避免在已经含云的背景上再画一次云。环境图保留晴空下半球的地面模型，可见背景才将地平线延伸到有限视距之外；它没有日月盘、星空和实际地形，因此不能称为完整 Photon sky map。

云填充来自当前更新的原始晴空向上/向下辐照度，直接光也取同次摘要。源 `d4a_generate_sky_sh.csh` 在天空合成后应用 skylight boost；因此云入射光会去掉该增强，避免黄昏时先增强云、再在 SH 中重复增强。可见云与环境云使用同样的原始晴空填充，不读取含云 SH，不会形成跨帧自反馈。宿主仍使用晴空 SH 的双半球求值，未逐项移植源单方向环境色模型。

## 发布与资源

先生成晴空图与 GPU 摘要，再合成环境图，最后读取最终摘要。原来 17×1 的 RGBA16F 摘要增加两个原始晴空辐照度像素，变为 19×1；异步 CPU 读回为 152 B。晴空图、环境图、SH、晴空辐照度和日月照明在同一回调原子发布。显式时钟跳跃、云开关和种子改变会作废陈旧提交，普通时间推进继续合并，最多每 250 ms 更新一次。

高画质体积云惰性增加两张 96×48 RGBA16F 图，共 73,728 B 公开颜色存储；摘要比原来增加 16 B。含云更新新增晴空摘要预绘制和环境云积分两次绘制，未复制主场景。高画质关闭云时保留少量热缓存，画质降到均衡后在晴空快照发布时释放；维度切换和上下文释放也销毁它们。192 像素宽度不变的画质切换保留已有晴空图，避免只因附加环境路径重建全部天空。

均衡/流畅仍使用原来的几何云与晴空环境；源 `BLOCKY_CLOUDS` 本来也不走体积云 sky-map 合成。闪电、源解析雾与极光反馈、完整跨层照明及更充分的动态过滤尚待完善。v16、视距 10、晴天雾 87.32～118、曝光与材质不因本批改动重设。

## 验证

`sky-cloud-feedback.spec.js` 在同一原生森林中仅切换环境捕获通路，保留可见云；实际 GPU 环境图经独立 CPU 源 SH 投影比较，并核对原始晴空辐照度。真实反射着色器的天空采样函数在上、侧、下方向读回，与环境纹理独立双线性采样比对。晴空图、云填充、直接光、镜头、时刻、曝光和雾保持一致，关闭恢复后的旧系数必须一致。另在黄昏增强大于 1.4 的时段检查入射单位，在明确标记的 time120 / 1920×1080 拍摄日间对照。

新增成本窗口强制调用真实天空更新，按关闭/开启/关闭顺序，每窗口预热 2 次后采 8 次 GPU query。计时只包围同步提交的天空绘制及异步读回发起，没有截图、`finish` 或其他帧绘制；它不是整帧 FPS，也不是所有设备的增量承诺。两种模式都保留原始晴空上下辐照度计算。

同一场景验证均衡画质释放云环境图且保留晴空纹理，再恢复高画质。相关回归检查延迟天空读回、满月/新月云补光，以及风和相机历史、遮挡揭露与真实上下文恢复。生产构建通过普通 UI 导入同一 v16 森林，切换云设置并导出，检查时间、位置和编辑保留，不依赖开发 API。

首轮晨景截图已实际查看：云色填充使厚冠层暗面和林下更明亮、偏暖，晴空背景保持相同。云型、工作色域、冠层细节和整体参考图仍有差距，数值与功能通过不代表美术验收完成。

最终 215 项 Node 检查、最新生产构建、4 项相关开发版浏览器检查及 1 项生产 UI 检查通过。首轮 Node 保留了两项仍使用旧云接口的失败；测试已按场准备和原始晴空输入更新，原来的画质/维度/开关及解析双半球断言保留。两个最终 GPU 批次期间 772 个受审计文件散列保持一致，结束后所属进程和独立监听端口为零。

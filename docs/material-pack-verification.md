## 使用与范围

暂停菜单的“方块资源包”可导入 ZIP、恢复默认。读取 `assets/minecraft/textures/block/*.png`，兼容旧 `blocks/` 路径和包外层目录。按现有方块名称和别名匹配，颜色、`_n`、`_s` 独立回退；方块模型、实体、物品独立贴图和任意命名空间未接入。沿用原生六棱几何，不能据此认为完整 Java 资源包模型兼容。

16/32/64 像素图集支持切换，更高分辨率降采样；设备纹理尺寸限制还可能降低到 32/16。纵向动画条带暂用首帧，不解析 mcmeta 动画。已有树叶/草顶保留本项目着色，尚未读取资源包群系 colormap 与完整草侧覆盖层。

原 ZIP 单独保存在 IndexedDB，刷新可恢复；不写入 v16 世界存档。浏览器无法保存时保留本次已应用结果并显示说明。无效 ZIP、无匹配图、过大数据、损坏 PNG 和通道尺寸不一致在发布前拒绝，保留当前材质。原包上限 32 MiB，只解压匹配的 PNG，并限制解压体积和像素数。

## 实际材质数据

以只读 Photon `6e67b36e818bacde0304edd49f28e2bb70e33f04` 的 `surface/material.glsl`、`lighting/bsdf.glsl`、`lighting/specular_lighting.glsl` 与 `program/gbuffers_all_solid.fsh` 为依据：

- `_s.R` 以 `(1-R)^2` 得粗糙度。G 区分介质、八种固定金属和 albedo 金属；固定金属保留源 F0/F82、Fresnel 和 albedo tint。沿用源硬编码基础参数，再按贴图更新。
- `_s.A` 驱动材质发光，255 是不发光哨兵。它不产生新的体素光源，也不更改方块的游戏照明属性。
- `_s.B` 的低区间提供孔隙率，进入湿面暗化和水洼覆盖；高区间解码 SSS 数据，但通用材质 SSS 尚未联通，不能算作已完成。
- `_n.RG` 重建切线法线，由真实几何和 UV 导数构建切线基；B 按源规则调整天空和方块光等级，A 高度保留在数据纹理中，POM 尚未接入。

颜色用 sRGB 图集；数值通道使用不经过颜色转换和 alpha 预乘的 DataTexture、最近邻采样。特别保留 alpha=0 时的 RGB，不能通过 Canvas 解码这些数值。PNG 使用 [fast-png](https://github.com/image-js/fast-png) 解码，ZIP 使用 Three 已附带的 fflate；新增分发许可见 `public/licenses/`。

镜面贴图存在时，共享保护 pass 从三个 RGBA8 附件扩展为四个；额外附件保存原始镜面值。正向光照与反射共用解码、法线和调整后的天空等级，普通石头也可由资源包获得倒影。只有相关网格可见时才触发既有 HDR 反射过滤。无镜面包时保持三个附件，恢复默认释放新增数值纹理与附件。未做独立材质反射历史或反射雾修正。

## 验证与保留失败

实际原生方块场景使用通过产品文件控件导入的合成资源包：石头变成有倾斜法线的金属，泥土具有介质镜面/孔隙率/发光，木板检验 255 不发光。诊断仅替换最终输出，读取实际地形 shader 的参数、法线、发光和孔隙率；另在生产反射 pass 边界读取场景与天空贡献。实际查看三方块截图，属于材质接入验收，不代表森林美术验收。

首轮读回的材料参数正确，但 WebGL 报 `GL_INVALID_VALUE`。原因是图集从 16× 增大到 32× 时 Three 仍复用旧不可变 GPU 存储。修复是在保留纹理对象身份的同时，尺寸变化时先 dispose，再上传新图；单块/手持物纹理同样处理。错误证据保留在 `pack-native-first`，修复后的完整流程通过。

同一浏览器流程还覆盖无效 ZIP 保留当前包、IndexedDB 刷新恢复、图形上下文恢复、恢复默认后数值纹理为空且附件回到三个，再次刷新保持默认。PNG 的 Node 检查覆盖透明 RGB、16 位量化、索引透明色、稀疏通道、尺寸拒绝和原生别名。默认高光、漫反射、环境反射及控件另做针对性回归；不把参数采样数当成游戏场景数。

209 项 Node 逻辑检查、8 项不同浏览器功能检查及生产构建通过。另有一项生产 UI 检查通过实际文件选择器导入颜色包，核对库存图标、IndexedDB 原 ZIP、恢复默认及导出的 v16 世界；已查看菜单截图。公式检查仍按一项测试计数。32× 测试包的图集为 512×4032，法线/镜面与标记数据共 16,517,084 B；900×650 的第四个 RGBA8 附件额外占 2,340,000 B。这些是已知资源大小，并非进程总显存或帧率测量。

保留两处夹具修正：UV 检查最初直接导入 node_modules 的 Three，产生重复实例警告，改为复用既有夹具依赖并重新通过；生产 UI 检查最初调用仅开发版开放的调试接口，导入已成功但检查失败，随后改用正式产品界面、浏览器数据和导出文件，通过后未给生产版增加调试接口。

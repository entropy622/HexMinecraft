# 树叶透光验证（0.78）

## 实施前判断

1. 结构：替换现有树叶的固定逆光增亮项，复用日月阴影深度与现有六棱光照体积，按沿光线的叶层厚度衰减透射。
2. 负担：不增加渲染目标、材质贴图、玩家设置或存档字段；保留原有风、镂空贴图、像素形状与普通漫反射。
3. 可推导：叶片识别来自实际世界方块，阻挡距离来自实际阴影图；不透明遮挡阻止透射，缺失光照数据时不凭天空亮度发光。
4. 复杂度：叶子只在光影档使用深度与体积数据，沿用现有质量、材料编译和上下文生命周期；不引入通用透射材质框架。
5. 泛化：三种树叶、日月、阴影 / 云影、屋顶与多层树冠、风动与水面捕获共用实际路径；不把石头、建筑和发光物体变成半透明材料。

参考 Photon 固定提交 `6e67b36e818bacde0304edd49f28e2bb70e33f04` 的 [厚度估计](https://github.com/sixthsurge/photon/blob/6e67b36e818bacde0304edd49f28e2bb70e33f04/shaders/include/lighting/shadows/pcss.glsl)与 [透射 / 相位近似](https://github.com/sixthsurge/photon/blob/6e67b36e818bacde0304edd49f28e2bb70e33f04/shaders/include/lighting/diffuse_lighting.glsl)。独立实现六棱体素近似，不打包 Photon 代码。

## 实施前失败类别

- 单层和厚树冠逆光同样发亮，或只按天空亮度调色；遮住太阳的石墙 / 薄建筑仍让背面的叶子发光。
- 测量仅比较截图总亮度，没有分离漫反射、体素光与新增透射；前后采样处于不同 TAA 相位或风相位。
- 透射不受真实光源 / 云影影响；深洞、无日月维度、阴影范围外仍发光；月光强于日光。
- 边界步进穿过六棱墙、跳过薄叶或产生边缘亮线；向下 / 负坐标不对；世界方块改变后体积分类未更新。
- 风动顶点与测量 / 阴影位置不同，镂空纹理不再起效；一树种生效而另两种失效；水面捕获使用错误相机或材质。
- 均衡 / 流畅编译原始深度采样而出错；新增 GPU 资源不释放；缩放、维度切换或 WebGL 恢复后残留错误。

## 结果

测量使用实际生产世界、叶片材质、日月阴影、六棱光照体积与线性 HDR 读回。在同一暂停帧连续打开 / 关闭既有 `leafSunColor`，分离新增透射与漫反射、体素环境光；不以截图总亮度代替透射。相机位于叶片背光侧 4 个世界单位、地面之上，移动后请求实际阴影刷新。可见叶片掩码从关闭透射时的绿色像素独立选取，避免只统计已经透光的像素。

| 同一镜头与 943 个叶片像素 | 0.77 固定逆光项 | 0.78 厚度透射 |
| ------------------------- | --------------- | ------------- |
| 薄叶新增透射平均亮度      | 0.015569        | 0.026255      |
| 多层树冠 / 薄叶           | 86.71%          | 1.39%         |
| 石屋顶遮挡 / 薄叶         | 77.72%          | 0%            |
| 去除遮挡后 / 初始薄叶     | 100%            | 100%          |
| 可见叶片上的透射覆盖      | 100%            | 100%          |

0.77 对照来自 `5690191` 的独立源码归档，运行相同镜头、光源和最终测量。旧版的屋顶遮挡断言按预期失败。初始新实现曾将普通阴影的法线偏移用于厚度射线，导致部分叶片误判为墙；独立掩码揭示覆盖只有约 20%。现在直接引用方向光实际更新的 `shadow.matrix`，以无偏移的风动世界位置计算厚度，覆盖恢复到 100%，普通 PCSS 接收面偏移不变。

- 薄半砖位于上层叶片之下时仍阻挡透射；实际光照体积读回叶片编码 12、半砖编码 13，移除后半砖位置恢复为空气编码 15。原天空 / RGB 传输和液体高度保留。
- 橡树、白桦、云杉均通过。实际生成云场在同一日照相位使透射降至晴空约 43.22%；月光透射为 0.002906，低于相同云杉日光，暂停风相位稳定，推进时间后画面改变且没有非有限值。
- 使用生产 `TREES` 定义搭建三树种树冠和真实水池；实际水面场景捕获有 57,673 个像素包含新增透射。光影 → 均衡 → 流畅 → 光影、800 × 600 缩放、阴影范围外的仍可见叶片、三维度与两次原生上下文恢复均通过，记录中的各阶段 GL 错误为 0、页面错误和 GPU 警告为空。

- `npm run check`：**95 / 95 逻辑检查通过，0.78.0 生产构建通过**，仍有既有大 bundle 提示。游戏逻辑未改动，本轮没有增加模拟 GLSL 的 Node 测试。

## 恢复路径的补充证据

扩展的实际场景在上下文恢复后移动镜头、切换维度时出现 `INVALID_OPERATION: delete: object does not belong to this context`。固定的 0.77 归档在相同资源释放场景中也复现，因此将 GPU 资源回调的清理纳入本轮：丢失时通知当前场景的几何、材质、贴图、阴影与后处理释放旧句柄，保留 CPU 数据；恢复后沿现有画质入口重建后处理。丢失期间不继续执行图形帧。没有更换 Three.js、包装或屏蔽 GL 错误，也不创建通用资源注册器。

## 范围与限制

- 仅光影档增加透射，沿用一张日月方向光阴影图；均衡 / 流畅继续普通叶片照明与风动。无日月维度、阴影图外或缺失体积数据不补造透射。
- 以最前方阴影深度限定光路，在现有六棱体积内精确走出每个单元，最多 48 个单元 / 48 个世界单位。叶层按 RGB 消光近似衰减，结合各向同性与前向相位；这不是完整几何次表面散射、透明彩色阴影或 LabPBR。
- 部分建筑以整个单元保守阻挡，缝隙可能偏暗；体素叶层不能完整表示镂空纹理内的真实叶密度。最近阴影投射面另取一次实际体积分类，以拒绝薄建筑和模型遮挡。
- 未扩展水下浸没叶片、草的次表面散射或模型皮肤透射；没有新增叶片运动矢量、专用历史或去噪器，不宣称解决所有风动时域稳定问题。
- 复用既有纹理和阴影数据，没有新增渲染目标、依赖、素材、玩家开关、持久化字段或存档迁移，v16 保存不变。光影档增加逐片纹理采样；这些检查使用软件渲染，没有对用户显卡帧率作承诺。
- 本轮改善光影与恢复路径，没有新增生物 / 地下群系；MC 玩法和 Photon 风格的持续目标仍在开发。

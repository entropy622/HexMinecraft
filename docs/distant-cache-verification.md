# 折返时复用远景源数据（0.129）

本批改善探索和折返时的等待，继续使用 0.128 的实际自然冠层、材质和 Photon 参考照明。完整 MC/Photon 目标仍在开发。

## 行为与容量

离开显示窗口时，远景网格仍立即移除并释放几何，只保留生成器返回的 CPU 数据。最多保留 169 片，类型数组的底层缓冲区另受 10 MiB 上限约束；共享底层缓冲区只计一次。缓存不保存网格、材质、GPU 目标、碰撞或生物模拟。

窗口切换先取出要返回的数据，再回收离开的窗口，避免后者挤掉前者。恢复数据按距视点的顺序重建网格，每帧仍最多处理两片；已排队的有效数据不会重复提交生成任务。网格使用当前资源包的布局和群系颜色，缓存中没有旧 UV 或旧 GPU 缓冲。

记录的方块、状态和流体修改会同时使所属数据片及相邻余量失效。切换窗口时先强制同步已记录修改，再取缓存，避免 250 ms 批量同步间隔内恢复旧建筑。旧版本、旧世界/维度和销毁后的晚到结果不能被复用。重新载入世界、换世界或释放远景组件时清空缓存。

## 验证与实测

7 项相关 Node 检查与生产构建通过。新增缓存检查覆盖复用次序、不保留退役网格、共享缓冲区计量、容量/超大替换、清空和真实已编辑数据片的版本拒绝；沿用的场生成/接缝/几何检查也通过。没有重跑未改动的高光公式矩阵。

最终开发版为 **1 项实际流程**，通过已有场景 API 移动并设置方块，运行真实生成 Worker、世界区块、光照与渲染；资源包和换世界使用现有导入控件。它不是正常步行或手动搭建的操作验收。A/B 两个相隔很远的区域各有 169 片，初次进入 B 新生成 169 片；返回 A、再次回 B 分别复用 169 片，新增生成任务均为零。A 中抽取的中心片，其全部类型数组在缓存返回前后 SHA256 指纹相同。

在 B 时将已保存的 A 区域同一坐标从木块替换为石块，并在同一次调用中立即返回，复用 **165 片**、新生成 **4 片**，覆盖该坐标及两侧余量。已检查真正显示核心的数据为石块，并查看相应实景。每个观测点都是 169 个远景网格、529 个近处玩法区块，页面与 GL 无异常。导入 seed625 后，世界实例更新，缓存条目/字节数及命中计数清零。

缓存 A 后在 B 导入 32× 叶片资源包，再返回 A，确认零新生成任务、源数组指纹保持，实景使用新材质；恢复默认材质后实景正常。已实际查看这些截图。

最终流程记录的时间如下。计时从场景 API 开始移动前起算，包含同步近景、真实光照/渲染和额外 40 个稳定帧；并非单独的缓存查询时间。

A/B 地形不同，这不是同区域关闭/开启缓存的配对性能实验，不能据此承诺固定加速比或所有场景的返回时间。首批记录新区域/折返约 75/27 秒，也表明耗时有波动。可以直接确认的是：上述未修改折返没有重复生成 169 片远景数据，但近景同步仍占明显时间。

发布版另有 **1 项真实控件流程**，在没有开发 API 的条件下导入/导出带高处方块的 v16 存档；观察实际 WebGL 远景混合参数到达 1 后，再记录和导出。时间、位置、天气、库存与编辑保持一致，页面/GL 无异常，未锁鼠标。发布流程验证初次显示与存档，不作为生产界面已覆盖全部折返操作的证据。

首批折返流程通过后，复核发现“刚同步完又编辑，并立即返回”仍可能赶在普通同步间隔内取出旧数据。最终实现对窗口切换强制同步，场景检查把编辑和返回放进同一个输入调用，并把计时窗设为刚完成上一批同步的时刻。保留首批数据，不能将它作为最终时序修正已经验收的证据。

## 限制

只保留有限的最近离开区域；更早区域会被逐出，刷新或重新加载世界也不复用。本批不缩短从未生成过的远景等待。返回时仍须生成近处玩法区块、重建显示网格、更新光照并稳定时域画面，不能把“零远景生成任务”说成瞬间返回。

每份完整缓存的类型数组约 8.48 MiB，另有少量对象开销；它增加 CPU 存储，没有增加 GPU 渲染目标。缓存容量和图形开销应分开看。本批保留 v16、完整视距 10、近景交接 87.32～118 与远景封边 176.12～238。

高处编辑方块仍使用既有柱组近似，孤立方块在样片中可扩成竖柱；缓存没有修复这一形状限制。悬挑、建筑内部和种植树的远景仍需改为更准确的占据。

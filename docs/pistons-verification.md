# 活塞与黏性活塞验证（0.79）

## 实施前判断

1. 结构：将推动与回拉接入实际红石调度、世界修改、建筑碰撞和库存路径，移动前先验证整条方块链，避免逐格试推留下半次操作。
2. 负担：沿用八向朝向、建筑的 `open` 伸出状态和已有红石计时器，不增加玩家设置、通用移动框架或另一套存档格式。
3. 可推导：推力方向来自放置朝向，供电来自实际网络，活塞头与底座关系由相邻位置和朝向推导；不存储可推导的配对 ID。
4. 复杂度：普通活塞与黏性活塞共享推动、阻挡、配对和实体接触路径，黏性仅在缩回时请求回拉一个接触方块。
5. 泛化：六个水平朝向与上下、负坐标和区块边界、普通方块 / 部分建筑 / 不可移动方块、稳定电源和脉冲、拆除 / 爆炸及保存继续都需通过真实路径。

最小完整机制需要先检查最多 12 个方块，再统一提交类型与方向状态；仅改变活塞模型或遇到一个方块就递归移动都不能保证守恒。容器与有独立运行数据的工作站采用不可移动规则；便携盒若被破坏，需保留完整物品栈内容。实体受推动，固定墙体限制位移，不能以实体占据空间为由取消整个活塞动作。

规则参考 [Minecraft 的活塞介绍](https://www.minecraft.net/en-us/article/block-week-piston)、[黏性活塞介绍](https://www.minecraft.net/en-us/article/sticky-piston)及 [官方红石指南](https://learn.microsoft.com/en-us/minecraft/creator/documents/redstoneguide?view=minecraft-bedrock-stable)。六棱世界将六面适配为六个水平面加上下，不声称复刻 Java 的准连接、BUD 或短脉冲吞块时序。

## 实施前失败类别

- 配方缩成七格后少付材料、不同木材填充失效；黏性配方不能保留普通活塞的物品守恒；创造菜单出现内部活塞头。
- 放置只支持水平面、正负方向翻转，或活塞被误认为需要地面支撑的红石元件。
- 13 格也能推、12 格不能推；链尾遇到黑曜石、基岩、世界边界或未加载区块时，链中已有方块被部分移动或复制。
- 供电从活塞正面错误触发；保持供电反复推动；撤去 / 恢复电源、阻挡解除后不再响应；同刻多个机关互相跳过延时。
- 黏性回拉整个方块链、穿过不可移动块或把脆弱方块拉成完整方块；普通活塞错误回拉。
- 半砖 / 楼梯朝向、树木轴向或另一只收回的活塞在移动后丢失状态；叶片错误地整格推动而不破坏；容器内容被凭空丢弃或复制。
- 活塞头没有实际碰撞 / 选取，或拆头复制底座掉落；底座被拆除 / 爆炸后留下孤立活塞头。
- 方块覆盖液体没有触发流体更新；移动支撑块后附着元件、掉落方块或植物不更新。
- 玩家 / 生物被方块吞没却没有推动；位移穿过固定墙体，或抬升时漏掉站在顶面的实体。
- 保存伸出或待发动作后拒绝加载、重复推动；头与底座不匹配的损坏保存被接受；卸载期间计时器继续运行。
- 画质、阴影、水面捕获、物品栏图标或缩放出现几何 / GL 错误，后台验证触发原生鼠标锁定。

## 结果

先写玩家端合成场景，在原 0.78 实现上通过实际工作台 UI 复现缺少活塞配方；`before.log` / `before/` 保留失败。实现后由同一玩家路径合成、放置、点击拉杆、推动、保存继续和缩回，不用直接调用活塞执行函数代替操作。

- 隔离场景使用真实 `World`、红石调度、碰撞和生产序列化。八个朝向在负坐标推动 12 格通过，加入第 13 格时整条链拒绝；黑曜石 / 基岩 / 门户 / 刷怪笼 / 容器和炉具阻挡不产生部分移动，移除阻挡后持续电源重新尝试。
- 黏性活塞只取回头前一格，保留上半楼梯的朝向与轴状态，不把后方整个链条拉回。九材料配方由现有七格堆叠配方支付，三种木板与普通 / 深板岩圆石组合均经过真实库存和合成函数检查。
- 伸出、待发和卸载延时均经过生产保存 / 恢复；区块外计时保持不变，恢复加载后只等待剩余时间。拆除头或底座会同时清理对应半部，包括未加载但已有编辑记录的头；破损配对保存被拒绝。
- 脆弱元件、洞穴植物与紫颂植物进入实际采集 / 掉落路径，便携盒成为保留内容的物品栈，液体由实际方块更新排开。新的掉落物在本次推动前生成，随同移动，避免被活塞头困住；移动支撑后的附着元件由现有维护入口处理。

- `npm run check`：**106 / 106** 逻辑检查和 **0.79.0** 生产构建通过；11 项新增隔离场景加入正常测试脚本，保留既有大 bundle 提示。
- 最终宽回归 **38 / 39** 通过，唯一失败是新增中键选头时，实际射线先命中拉杆的支撑石 `(1,44,0)`。调整到另一侧的实际站立观察位后定向复查；没有改动产品选取或放宽目标断言。
- 定向复查 **6 / 6** 通过，包含五项活塞玩家场景和扩展的实际 UI 场景；所有原动作 / 碰撞断言保留。归一化结果记录站立高度 43、没有蹲伏，便携盒完整保留七颗钻石，拆头后底座一件 / 头零件，紫颂花只掉落一份且生长记录为空。合计 39 个开发场景有通过记录，不把宽批次记成一次全绿。
- 补齐手持模型后的最终定向复查 **6 / 6** 通过（`held-model-six.log` / `held-model-six/`）。新增真实黏性活塞手持几何断言与 F 键主副手交换，普通活塞在主手和副手分别记录 96 个顶点；前述推动、内容、站姿和保存断言全部保留。

## 检查中发现的问题

玩家抬升场景曾失败，按站立眼高换算得到 `42.59575`，未达到原 `>42.9` 阈值。排查发现第一次相交采样已晚于真实接触，以它计算剩余位移会使脚部仍嵌入新位置的方块，下一轮碰撞触发自动蹲伏。改为从前一个采样点推算保守位移，新增最终 `bodyClear` 与不蹲伏断言，保留原抬升阈值；玩家实际抬高一格后保持站立。

差异复核发现紫颂花的普通移动分支只会搬走类型，无法保留独立生长状态。因此主动中止首个宽回归批次，接入既有 `harvestChorus`，增加真实花朵破坏、单份掉落、无孤立生长记录及保存继续场景。中止批次只作为过程记录，不计为完整通过。该缺口由源码审查发现，后续场景验证修正后的实际行为。

首次正式 UI 检查的快捷栏与错误记录通过，但人工查看截图发现手中没有活塞。先在真实黏性活塞合成 / 选择场景补入几何检查，复现已选择 `stickyPiston` 却有 0 个模型顶点（`held-model-before.log` / `held-model-before/`）。随后将手持与掉落物重复的 23 种部分建筑路由合并至 `building-graphics.js` 的 `usesBuildingItemMesh`，保留原有成员并加入活塞。修正后主副手实际几何、原操作场景和新构建截图均通过；首次元数据通过不作为最终画面验收。

测试准备也有三处改正：瞄准从只核对类型改为同时核对实际坐标 / 层高 / 类型，避免使用前一帧的石头目标；拉杆瞄准其真实底座而非偏离杆柄的中心上空；创造模式改由实际物品库取出活塞并放入快捷栏，保留物品守恒。早期失败采集曾试图序列化目标 Mesh，后改为只保留坐标、法线等诊断值。没有为通过检查添加产品专用入口或放宽动作断言。

所有自动化使用后台无头 Chrome、独立的 5174 开发测试端口 / Vite 缓存与 5176 生产预览端口。`browser-fixture.js` 只在设备边界替代原生 Pointer Lock，没有操作前台鼠标。已查看真实活塞头 / 底座 / 杆与便携盒掉落画面；平整平台是可控检查场景，不代表完整世界美术验收。

## 范围与限制

- 八向适配六棱世界，普通与黏性共用最多 12 格的线性推动，黏性回拉一格。没有新增黏液 / 蜂蜜块粘连、Java 准连接、BUD、短脉冲吞块或完整邻居更新顺序。
- 九材料配方沿用七格堆叠布局，压缩格内仍须按同种物品叠放，未重做 MC 九宫格合成 UI。
- 当前在 0.1 秒调度边界提交整体位移，模型显示正确伸出 / 收回形状；没有连续移动方块的渲染插值或跨帧物理占用。
- 实体接触使用既有部分建筑形状和身体样本，沿运动采 33 点，固定障碍位移步长最多 0.04。起点保守前移与小间距避免重叠，未引入连续碰撞求解或复杂挤压群体模拟。同刻机关按当前调度顺序提交，不声称 Java 逐项更新等价。
- 当前适配玩家、常规生物、村民、船和散落物；经验球 / 弹道没有新增推动规则。挤压在动作发生时调用现有伤害，未扩展持续窒息系统；村民现有模型没有独立生命值，保持受推而不增加新的死亡系统。
- 容器和具有独立运行数据的方块不搬运；便携盒破坏后携带内容。植被调用既有掉落规则；常规作物仍由既有生长 / 支撑检查处理。未新增搬运容器的保存协议或持久运动记录。
- 沿用现有 v16 保存、质量、体素光 / 阴影和资源恢复。材质由程序绘制，不新增外部素材、依赖、渲染目标或玩家设置。本轮继续补充 MC 机关，未增加群系 / 生物，也未增加 Photon 着色项，持续目标仍未完成。

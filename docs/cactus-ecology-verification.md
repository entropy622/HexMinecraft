# Cactus ecology verification

## Design gate, written before implementation

1. Structural: one cactus lifecycle must connect world growth, support loss, real collision contact, entity damage, item destruction and ordinary saves.
2. Burden: players gain no setting; only the existing block-state record gains an optional integer `age` for cactus, defaulting to zero.
3. Determinable: support, height, occupancy and contact are measured from the loaded world and existing shapes; callers supply no precomputed answers.
4. Gratuitous: use the existing plant maintenance/random-tick cadence, shape builder, damage/loot and crafting paths; add no scheduler or compatibility format.
5. Overfitted: cover all six hex neighbors, all supported dimensions, natural and placed stems, ordinary entities and arbitrary dropped stacks.

Smallest sufficient change: a cactus module for random ticks and physical contact, corrected pigment support, and narrow integrations into existing world/entity/item paths. A decorative block or collision-only flag cannot implement growth or contact damage; a second growth registry would duplicate the existing persisted block states.

## Reference and explicit adaptation

Target is **Minecraft Java 1.21.5**. The [official release notes](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21-5) introduce cactus flowers: a 10% opportunity on one/two-block stems, 25% on three-or-more-block stems, flower support on cactus/farmland/center-supported top faces, and one flower crafting one pink dye. The [official cactus article](https://www.minecraft.net/en-us/article/block-week-cactus) specifies one health point per contact hit.

Exact static checks use Mojang's [official server JAR](https://piston-data.mojang.com/v1/objects/e6ec2f64e6080b9b5d9b471b291c33cc7f509733/server.jar), SHA-1 `e6ec2f64e6080b9b5d9b471b291c33cc7f509733`, and [official mappings](https://piston-data.mojang.com/v1/objects/f4812c1d66d0098a94616b19c21829e591d0af3a/server.txt), SHA-1 `f4812c1d66d0098a94616b19c21829e591d0af3a`. REA opened the archive as ZIP with SHA-256 `ae7681dadce21b6b4017d28e7eb567d86b6c100a6969994f540b9e54f812dc29`. `javap -c -p` on the bundled server class `doa` (`CactusBlock`, mapped lines 57–86) establishes the age-eight flower opportunity, age-fifteen growth/reset, three-block natural growth limit, air-above requirement, and no light or hydration threshold. `doa.canSurvive` checks horizontal `BlockState.isSolid`/lava, sand or cactus below, and no liquid block above. `dob` (`CactusFlowerBlock`) accepts cactus, farmland or `SupportType.CENTER`; it does not require clear sides after planting. `ebp$a.calculateSolid` distinguishes legacy solidity from transparency and collision, with explicit block overrides and collision bounds. `dvz$2` defines the center support footprint. Local disassembly remains ignored under `test-results/cactus-official-source/`; no upstream code, mappings or JAR is committed. These are static observations, not execution of the original game.

The square game's four horizontal faces map to all six hex faces. The existing 8×8×64 chunks use the grass module's 60 random cell samples per simulated second (same 4096-cell volume as a Java section). Maintenance runs on the existing one-second game cadence, pauses freeze it, and unloaded chunks do not catch up. The new full-cell damage envelope surrounds the inset 14/16-wide stem; collision is 15/16 high while its visible outline remains one block high. Original generated 1–3-block desert stems remain; flowers become obtainable by their actual growth. The repository has no composter, so the flower's integrated use is its ordinary 1:1 pink-dye recipe.

Legacy solidity normalizes existing hex collision bounds before using Java's `35/48` average-span/full-height test, retaining the verified forced-solid web/fence/gate/dripstone exceptions. Flower center support uses a two-pixel central hex footprint scaled to this world's face width; cactus and farmland retain their explicit special cases. Entity contact uses the same player/fauna body dimensions as movement, including the chicken's smaller radius and the ghast's larger reach. Existing armor calculation applies, cactus hurt intervals are half a second, and environmental mob deaths use the ordinary loot path without adding player XP credit.

## Failure classes, written before product code

- Growth: age 0, 7, 8, 14 and 15; exact 10%/25% probability boundaries; failed flower rolls; one/two/three/taller manually placed columns; correct parent reset and new-block default; blocked or liquid-filled headroom; a liquid two blocks above; no light, water, biome or dimension requirement; neither lower stems nor age-15 tall stems progress; illegal newly grown stems break and drop through normal maintenance.
- Support: sand/cactus accepted, every other base rejected; all six solid/lava neighbors reject; water/glow neighbors allowed; transparent glass and partial solid slabs/fences differ from non-solid carpets/flowers/circuits; own-cell liquids reject; unloaded borders never masquerade as air; removing any stem breaks the unsupported upper chain and flower once; unchanged neighbors do not duplicate drops.
- Flowers: age-eight growth checks its own space and cactus survival at the new cell; solid/lava sides or liquid above suppress the flower opportunity; a placed flower accepts cactus/farmland and actual top-center support, including upper slabs and posts; air, water, low slabs, open gates and hollow tops fail; no collision or spike damage on the flower; support loss/water wash drops one flower; ordinary mining and pink dye crafting consume/produce the expected counts; occupied tips stop cactus aging.
- Contact: all six side faces, top, corners, different entity radii/heights, exact non-overlap, outside neighboring cell, negative coordinates, high-speed item movement; inset collision leaves a real contact margin; standing on the 15/16 top hurts; safe nearby entities and standing one full block above do not hurt.
- Entities: players take one point with existing invulnerability/creative/armor handling; animals take repeated bounded hits, die through normal loot without player XP; fire immunity does not grant cactus immunity; removed/dead mobs are not hit again; no contact means no damage; items are destroyed before pickup/attraction, including cactus/flowers/equipment/portable contents, while safe stacks persist and unloaded stacks freeze.
- Persistence/observers: absent age equals zero; age changes notify observers but default-zero writes do not; ages 0..15 survive save/import/continue/chunk streaming; reject negative, fractional, oversized, string/null/NaN and non-cactus ages; natural stems receive a recorded cactus edit when aging; replacement/removal clears state; no separate save version or timing data.
- Integration: renderer and collision use the same inset footprint, GL stays clean, errors remain empty, 0.84 grass/carpet/observer behavior and all existing Node/build/format gates remain intact.

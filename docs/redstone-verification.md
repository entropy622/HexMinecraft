# 0.56 红石与灯光验证

本轮基于 `e8b5a14`，日期 2026-10-26。加入可放置的红石粉、拉杆、石按钮、石质压力板与红石灯，连接既有门 / 栅栏门 / 活板门、库存、采掘、支撑、液体、光照和保存路径。未增加依赖或下载素材。

## 行为与证据

- Node 使用生产 `World` 检查六向传播、负坐标区块边界、15 级衰减、多输入取最大值、闭环断电、逐级上下线、净空阻断、实心支撑强供电与弱供电不再供线。
- 按钮一秒释放，按下时重复触发不延长；压力板只接受脚部接近的生物体，离开后保留半秒信号。卸载区域冻结计时，生产序列化恢复后继续。门的供电边沿保留手动覆盖，被阻挡时重试。
- 生存配方通过实际槽位填料和合成消耗验证，包括工作台限制。存档校验拒绝错误供电值、安装面、孤立 / 重复 / 超时计时器及漏失的活动计时。
- 灯面有独立发光材质；环境体素场中，灯上方 RGB 从 `[0,0,0]` 变为 `[14,12,8]`，熄灯后归零。浏览器另外检查实际地面网格属性，通电约 `[0.7511,0.5378,0.2178]`，熄灯为 `[0,0,0]`。同时人工查看暗室通断截图，避免仅以逻辑状态证明照明。
- 浏览器走真实射线放置一段线路与拉杆，确认消耗红石粉，拉杆到三段线为 `[15,14,13]`；保存 / 重载后继续供电。拆除支撑或放入水源会使线路掉落红石粉、灯失电。
- 墙面拉杆通过支撑石块为相邻灯供电；顶面按钮可按下，两个元件在支撑拆除后掉落。玩家实际走上压力板开门，离开后关门；按钮在暂停菜单内冻结，重载后释放。
- 触屏场景从移动端 UI 进入游戏，实际点击「交」启用拉杆和灯，未请求原生鼠标锁定。受控活板门改变支撑时，传播器在下一物理步重算，防止已经掉落的线路继续留有信号。

浏览器截图与 JSON 位于 `test-results/`：`powered-circuit.png`、`unpowered-circuit.png`、`wall-lever.png`、`ceiling-button.png`、`pressure-door.png` 及对应的验证清单。该目录会被下一次 Playwright 运行覆盖。

`npm run check` 通过，包含 32 项 Node 测试与生产构建；既有大包提示仍在，主包约 1.188 MB。浏览器分批覆盖 11 个指定场景，包括本轮四项红石交互、洞穴通行 / 保存 / 光照、真实采掘、材料库、三档画质 / 三维度，以及上一轮的三项操作回归。未执行全部历史浏览器场景。

## 设计复核与限制

新字段的用途限定为安装面 `mount`、输入 / 消费方块的供电边沿 `powered`、按钮 / 压力板剩余时间 `redstoneTimers`。信号强度、已加载元件索引和强弱供电集合均可从世界重建。复用已有 `lightRevision` 判断拓扑变化，逐物理步检查踩板；受控门沿用原碰撞规则，失败操作不会反复弹提示。新增地面 / 墙面 / 顶面模型共用既有几何渲染、图标、手持与掉落路径。

最小方案为一个传播器、元件定义和元件几何文件；没有事件总线、图数据库或另一套库存 / 碰撞框架。分批刷新体素光的队列优先处理实际修改的区块，避免灯灭后近处地面长时间留着旧光。

存档为 v15，旧 v14 记录不覆盖、不迁移。线路在已加载区域内模拟，卸载后不向远处提供信号；这里不提供区块加载器。实心块、全高双半砖可导电，上半砖可支撑线路，楼梯与透明方块不在本轮导电模型中。尚无中继器、比较器、活塞、红石火把，未模拟 Java 的准连接与更新顺序；灯的信号响应没有 MC 的额外熄灭延时。光影沿用现有 Photon 风格体素光与散射，没有新增反射或时域算法。

基础规则参考 [Microsoft 的 Minecraft 红石指南](https://learn.microsoft.com/en-us/minecraft/creator/documents/redstoneguide?view=minecraft-bedrock-stable)，六向网络与模型独立实现。代码复核覆盖本轮全部修改 diff 与新文件；验证不等于全部历史玩法或完整 MC 对等验收。

本轮净增产品代码 / UI 625 行、测试 765 行、文档 48 行、配置 0 行。测试增长集中在可搭建线路、实际输入、存档、光照网格和支撑反馈；没有引入额外运行时依赖或兼容分支。

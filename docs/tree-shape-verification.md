# 树高、树冠和高橡树分枝

0.110 改进天然森林与树苗的几何结构。上一版普通橡树固定为 4 格树干，冠层由完整半径 2/2/1 六边形层组成，林冠容易连成平顶。本批使用同一个 `treeCells` 生成天然与种植树，没有另加装饰冠层或不参与玩法的远景树。

## 范围和来源

普通橡树干高 4～6，白桦 5～7；树冠有四层，底部和六个角点按确定性哈希裁切，顶层保留中心及部分邻叶。约 18% 橡树使用 7～9 格主干和两条错层枝干，枝端形成不同高度的小冠层。分枝路径是相邻六边形和竖向方块的连接，横向原木沿用已有三种水平轴。树种、树根出现位置、群系和地形高度没有改变，云杉、丛林树和绯红树的布局函数保留原规则。

参考 Mojang 官方 1.21.5 客户端与映射中的 `TreeFeatures`、`TrunkPlacer`、`BlobFoliagePlacer` 和 `FancyTrunkPlacer`：小橡树的直干参数为 4/2/0，树高由基本高度及随机项组合；叶片按层和角点筛选，大橡树具有枝干与冠层附着点。这些是行为参考。六边形距离、18% 宿主变体比例、枝干路径与冠层布局为独立实现，没有逐项复刻 Java 大橡树算法，也不包含 2×2 巨树、藤蔓或新树种。

[官方版本元数据](https://piston-meta.mojang.com/v1/packages/cd7d9c7e497cc3b036ec6aa6e6baba94a4a790df/1.21.5.json)；客户端 SHA1 `b88808bbb3da8d9f453694b5d8f74a3396f1a533`，映射 SHA1 `57669731d542f98646772e91a0d68628f9827a5c`。静态字节码证据存于外部产物 `tree-bytecode.txt`，没有分发 JAR、映射、反编译源码或新增纹理。

## 世界和存档

冠层最大水平六边形距离仍为 3，沿用原来的三列生成 halo。所有结果只依赖种子、树根坐标和树种，正负区块按不同顺序加载得到同样的方块与枝干轴。枝干不会覆写地形或其他非叶片方块；玩家编辑仍在天然生成后应用。种植前完整检查树冠/枝干位置的加载、占据、液体、世界高度和建筑叶块，失败时不会只生成半棵树。

天然枝干轴写入可重建的自然状态；树苗长成的枝干则用原来的 `setState` 和 v16 方块状态保存。不修改存档格式。旧存档继续读取，但未编辑的天然树会按新规则再生，不能保证旧天然林冠逐块不变；已保存的采集/放置及种植树编辑继续覆盖生成结果。

首轮存档检查暴露了状态调用缺少必需的 `facing/open` 字段。天然枝干状态及实际树苗生长调用现补齐这些字段，沿用原有校验，没有放宽存档格式。

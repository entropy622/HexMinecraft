# 远景建筑的悬空、开口与透明玻璃（0.130）

修复 0.127～0.129 远景柱组将一个高处方块扩成落地柱、填满建筑内部的问题。完整 MC/Photon 目标和用户森林参考图仍在开发。

## 显示行为

建筑、种植树、记录的方块修改及流体表面按真实一格占据保存，保留屋顶下方、楼板之间和门窗中的空气。村庄和遗迹只在远景生成器的临时世界中记录生成单元，普通玩法世界不分配该记录，也不将其写入存档。

半砖记录上下边界，原木保留横放方向，流体使用现有实际液面高度。稀疏元数据以 7 位量化单元内高度，半高误差小于 0.005 格。已编辑地表组在需要时恢复实际剩余单元，避免邻列较高的简化地表盖住改过的表面。

自然地形仍使用水平四格简化，自然树冠使用水平两格、竖直一格的占据。精确修改与自然树冠相交时，该小组改为真实逐格单元；挖除产生的空气也参与这一规则，不能只检查仍有方块的编辑。

玻璃使用单独透明材质组，沿用现有图集、照明和云影。远景目标内的 RGB 按 alpha 还原后再与天空、边界雾组合，避免再次乘透明度造成发黑。没有增加渲染目标；几何颜色增加一个 alpha 字节。

## 实际验证

相关 Node 检查通过，覆盖四项建筑/形状检查、四项已有场生成/接缝检查和三项缓存检查。新反例确认：修改前，挖掉单片自然树叶仍留下非空的简化树冠单元；修复后保留真实空气和相邻叶片。孤立金属方块的几何仅出现在实际高度，悬空屋顶有底面，半砖、横梁、液面与玻璃材质组分别检查。生产构建及改动文件格式检查通过。

最终开发版为 **一项实际 GPU 流程**：通过现有存档控件导入跨数据片的悬空房间、玻璃、横梁、半砖、水源和种植树夹具，检查真正显示核心中的屋顶、室内空气与孤立方块。查看完整画面与隐藏玻璃的对照，切换三个画质档，再执行真实 WebGL 上下文丢失与恢复。它验证导入后的显示，不代表已覆盖正常种植、搭建和采掘的全部操作。

独立玻璃板在远景目标中读回 alpha 为 **0.6162109375**，处于透明范围；恢复后该 RGBA 值、几何与数据字节数一致。场景有 169 个远景网格和 529 个玩法区块，页面及 GL 无异常。最终实景截图已查看。

同一夹具中，远景几何属性和索引合计 **82,973,866 B，约 79.13 MiB**，生成类型数组 **9,267,504 B，约 8.84 MiB**。这是该镜头的已知资源数据，并非进程总显存；夹具、相机与此前自然森林不同，不能用于宣称帧率或内存的配对收益。复杂建筑会增加精确单元，缓存仍受 169 片及 10 MiB 上限约束。

发布版另有 **一项真实控件流程**：没有开发 API，通过导入/导出同一份 v16 存档，观察实际远景混合达到完整显示，确认时间、位置、天气、库存、方块、方块状态和流体保持一致，页面及 GL 无异常、鼠标未锁定。没有重跑未修改的高光公式输入矩阵。

最终两批捕获期间 871 个输入文件无散列变化；源码冻结结束后才补充本页等文档。所有批次的所属进程与独立 5191/5193 监听端口均已清零。浏览器串行、后台 headless，并使用 Pointer Lock mock，未操作前台鼠标或用户的 5173 服务。

## 限制与追溯

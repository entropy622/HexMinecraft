# 首帧时钟与大气平滑

固定镜头的真实 GPU 捕获中发现负雾密度，最低记录约 -0.18025。旧版 4a5c732 的开阔天空也记录到 -0.01245。正密度目标的正常平滑不应产生这些值。

帧循环用 performance.now() 初始化 last，再与首个 requestAnimationFrame 的帧时间戳相减。长初始化或回调调度延迟会使首个帧时间戳早于初始化时刻，现有上限没有阻止负 dt。Three 的指数平滑在负时间下外推，可能大幅越过目标；同一 dt 还会传给模拟和其他视觉效果。

回归仅在外部 rAF 边界模拟一次延迟，观察并转发实际 Graphics.frame 调用。它不修改雾、天空、相机、光源、平滑函数或渲染结果。要求真实渲染与模拟收到的步长都在 0..0.25 秒，雾密度为有限非负值。固定参考场景增加实际雾密度和相机天光的物理范围检查。

修复采用同一个 rAF 时钟计算相邻帧间隔，首帧步长为零，并保留现有 0.25 秒上限。旧版实跑收到 -39.741 秒，雾密度变为约 -1.523×10³⁰；修复后同一外部边界回归 1/1 通过，首帧为零，后续均在 0..0.25 秒，雾密度约 0.00914，页面错误与警告为零。首轮失败、trace、JSON 和进程/端口清理记录保存在本机 hexminecraft-photon-0.87/frame-clock-red 与 frame-clock-green。

历史黑帧没有完整记录首帧时钟和雾密度，尚不能据此证明每一次黑帧的根因；其原图与前景亮度门槛继续保留。云形态的配对会对旧云和新云共同应用这份时钟修复，避免把无效平滑状态当成云光学差异。

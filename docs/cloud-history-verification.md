# 云层时域重投影验证（0.74）

## 实施前判断

1. 结构：在云本身的散射与透射积分中复用历史，解决云被最终 TAA 排除后的采样跳动，不修改整个场景的反应遮罩。
2. 负担：复用光影档、云开关、实际相机与云场，不新增玩家参数或测试开关。
3. 可推导：由积分的代表距离、当前和上一帧相机及风位移推导重投影；由场景深度和云距离决定遮挡与历史有效性。
4. 复杂度：只在现有云 pass 中添加多附件数据与历史解析，主画面和水面捕获分别保存，避免把不同投影混入一份历史。
5. 泛化：覆盖移动、风、天气、建筑显隐、云内外、传送、尺寸、种子、维度、上下文恢复与故障恢复，不为某一截图调参。

最小方案是当前积分加一份深度数据、每个实际视图的双缓冲历史及一次解析；复用现有半分辨率、合成与游戏时钟。仅在最终画面混色会混入地形、天空和水面；只增加步数不能提供时域稳定性。代表距离来自真实积分，避免把所有云投到同一水平面。

参考 Photon 固定提交的 [云重投影、风补偿与深度拒绝](https://github.com/sixthsurge/photon/blob/6e67b36e818bacde0304edd49f28e2bb70e33f04/shaders/program/d2_clouds_upscaling.fsh)，独立适配本项目的单层云场。

## 实施前失败类别

- 固定场景在 TAA 亚像素投影变化下持续跳动，稳定后没有降低时间方差；只用模糊换稳定或改变平均透射率。
- 风向或相机重投影符号错误；历史留在屏幕上、抹平云边、变暗或拖尾。
- 当前或上一帧有前景建筑，仍混入被遮挡的云；拆除遮挡后沿用建筑空云。
- 主视图与水面 / 水下扩大投影视图污染同一份历史。
- 天气、光照突变、传送、镜头、种子、尺寸、维度与关闭再开启继续读取过期历史。
- 多附件着色器编译失败、读写反馈、NaN、没有恢复目标 / autoClear / 镜头，或销毁遗漏 GPU 资源。
- 云被再次送入最终场景 TAA 后双重累积，或旧水面、天空透射与地下遮挡回归。

## 结果

- 最初测量原始场景透射缓冲，旧版的 48 帧前后方差比为 1，新版为 0.715；这一指标混入正常投影位移，不用于最终质量结论。
- 最终收敛用例读取游戏实际完成投影对齐的 TAA 输出。旧版完整 Git 快照在独立 5175 端口再次失败，方差比为 0.9983；新版约为 0.0533，保留约 95.9% 的初始邻域细节强度，初期与稳态平均颜色均方根差约 0.00446。固定场景稳态绝对方差与旧版相近，不能把新积分自身的收敛比例表述成相对旧版降噪 95%。
- 原有四项云场景与新增两项组成六项批次，全数通过。覆盖实际建筑透射、云影与云内外、天气 / 种子 / 夜晚、水面捕获、故障恢复、尺寸、销毁与维度。
- 加强移动检查后，直接比较原始透射场在建筑边缘得到 0.0359 的差异；按实际投影偏移对齐 GPU 读回后通过。没有为这次指标错误添加产品补丁。
- 强化场景中相机平移后逐帧推进 64 秒实际云时钟，历史年龄达到上限 32，透射场与清空历史后重新积累的参考图误差约 0.00471。云前建筑完全遮挡；云中建筑仍保留约 0.0828 的透射，清空历史后的值约 0.0897，场误差约 0.0210；移开后及时恢复。
- 使用真实 `WEBGL_lose_context` 丢失并恢复上下文，两份历史在恢复事件中均归零。重新积累后数据有限、GL 错误为 0，与参考透射场误差约 0.000522。
- 水下捕获与主视图的投影比例为 0.4，四个历史目标的八张纹理独立；窗口尺寸变化后全部保持半分辨率；画质降低时四个历史目标全部触发销毁。渲染故障会清空历史并恢复目标、autoClear 和镜头，下一帧恢复。
- 最终跨效果批次 14 项全部通过，用时 10.6 分钟，包括跨维度画质 1、TAA 3、水下界面 4、雨后地表 6；与云场景合计 20 个不同场景分批通过。TAA / 水面故障日志来自刻意的 GPU 边界注入，恢复断言通过，没有未处理的新增编译错误。
- `npm run check` 的 83 项逻辑测试全部通过，生产构建成功；保留已有包体积提示。全部改动文件通过 Prettier，`git diff --check` 通过。

全部浏览器使用现有 Pointer Lock 设备边界替身，在后台无头 Chrome / SwiftShader 中运行，没有接管前台鼠标。当前树使用独立 5174，旧版快照使用 5175；未修改用户的 5173 测试页面设置。浏览器运行时没有编辑源码、测试或文档。

## 实现与范围

保留 24 次当前帧积分，在每段内分帧偏移起点；MRT 同时输出积分颜色 / 透射与代表云距离 / 场景距离。历史按渲染源目标区分，两份半分辨率附件保存颜色和距离 / 年龄数据，各自双缓冲；重新投影后按先前深度拒绝无效样本，并限制在当前 3×3 邻域范围。最终场景 TAA 继续把云标为动态区域，避免混入天空和背景历史。

由当前与历史相机、投影比例、风、纹理版本、云厚度 / 覆盖和光照推导失效，不增加用户配置或测试参数。尺寸与世界重建清空已有状态；复用现有上下文恢复事件，没有第二份全局监听器。资源随既有画质生命周期释放。

这仍是单层、有限步数和代表距离的近似；没有复刻 Photon 的多层天气、完整时域上采样、复杂云形变化或更精细的运动估计。新增历史会提高光影档的 GPU 内存占用；后台软件渲染通过不代表真实硬件帧率验收。已查看实际云层截图，未引入外部贴图、依赖或存档版本。

逐行复核本轮 `cloud-volume.js`、`graphics.js`、`temporal-pass.js`、新增 `cloud-history.spec.js`、扩展的 `clouds.spec.js`，以及 README、开发状态、当前验证记录和两个版本文件。没有未审阅的改动文件。

- 历史按已有场景源目标键控，只对应主画面与实际水体捕获，不增加调用者填写的视图 ID 或用户参数。当前颜色、场景深度和代表云距离都是本轮积分已经掌握的数据。
- 跨帧相机、投影比例、风、噪声版本、云形和光照快照均用于重投影或失效检测；这些上一帧的数据无法从已经更新的当前相机直接取回。帧数同时用于可用性和分帧采样，没有重复的有效性标记。
- 新增解析材质与本类共享全屏 quad；不另建单调用者类或平行管线。历史颜色与元数据双缓冲防止 GPU 读写反馈；现有合成和复制保留原场景深度。

- GPU 元数据的年龄用于解析权重，未写入无人读取的诊断字段；相机与天气规则由系统测量，未增加测试专用产品参数、存档数据或依赖。

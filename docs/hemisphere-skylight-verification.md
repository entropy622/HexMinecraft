# Photon 上半球天光

0.108 迁移源天空球谐投影，使实际照明继续接近 Photon 的生产路径。整体森林参考图和绝大部分可迁移功能的目标仍未完成。

## 实现

固定只读 Photon `6e67b36e818bacde0304edd49f28e2bb70e33f04` 的 `program/d4a_generate_sky_sh.csh` 使用 256 个 R2 样本，将均匀球面方向折叠到向上半球，以 `2π/256` 投影天空图。此前宿主使用 512 点经纬中点全球积分，会把下半球查表也计入天光。

`src/photon-skylight.js` 接入源采样及投影规则。源一阶系数按 x/z/y 排列，Three 按 y/z/x；此外源最后两个二阶基函数的归一化是标准基的 `1/√2`。源投影和求值都含该因子，转换到宿主标准求值器时，等效系数必须乘 `1/2`，不能仅交换数组顺序。相同转换同时适用于 Three 普通 LightProbe 和已有 AO 可见锥求值。

GPU 仍在现有 17×1 归约中生成 9 个 RGB 系数，与天空图、日月方向/光色及其余摘要一起原子发布。主世界三个画质档共用该路径；云的上下方向照明、叶片环境透光和空气的平均辐亮度读取同一快照。空气使用完整球面平均的单位约定，因此缺失的下半球贡献不会被人为乘二。日月直接光、曝光与调色未因这次投影迁移改动。

这是源投影核心的宿主适配：当前输入仍为晴空大气图，未将真实云和源天空的解析雾合成回该图。仍缺源完整环境反馈、GTAO bent normal 和更充分的林冠标定。原有低层散射、材质阴影反弹继续各用自己的路径。

## 对照与证据范围

`tests/photon-skylight.spec.js` 的公式检查是一项浏览器测试。真实 GPU 从可控 HDR 天空图投影，然后照亮真实 Lambert 平面；独立 CPU 参考使用 Photon 自己的系数约定和卷积核，而非调用生产 GLSL。覆盖常量天空、定向/二阶变化、HDR、不同表面方向、天光门控和下半球颜色替换。改变下半球不改变输出系数。既有天空输运检查按新半球约定更新参考，仍保留误差、介质边界、陈旧读回和异常要求。

自然森林保留 seed624、time30、FOV72、曝光1和原材质，在同一进程依次使用旧全球投影、新半球投影、恢复旧投影。每组等待天空发布和时域稳定，记录直接光/天空/系数/镜头/雾；恢复后旧系数逐位一致。旧控制只替换投影，不回退其他渲染算法。截图不是冻结 HDR 的逐像素差分。

已查看首轮 900×650 对照。向上辐照度从约 `[0.519, 0.603, 1.103]` 变为 `[0.571, 0.645, 1.143]`；实际晨景差异较小，仍明显偏暖、偏橄榄色，云形和树冠轮廓也与用户参考图有差距。不能把数值一致性当成森林美术验收。

另保留明确标注的 time120、1920×1080 白天对照，用于区分时段颜色和投影差异；不能把它与 time30 旧图作为单因素比较。固定晨景未替换。
